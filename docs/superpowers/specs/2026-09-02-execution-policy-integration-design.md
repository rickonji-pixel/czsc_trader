# 执行规则晋升、回测与日频建议集成设计

日期：2026-09-02
分支：`codex/0902-execution-policy-research`

## 1. 目标

将`0902_EX02`冻结的执行规则晋升为活动执行规则，并接入两个正式入口：

1. 回测对比同时展示活动基线的次日开盘理论口径与执行规则口径；
2. `czsc-trader advice run`基于最新完整收盘数据生成下一交易日的人工委托建议。

活动信号基线继续决定目标仓位`0/1`。执行规则只负责目标仓位与明确传入的实际仓位不一致时的委托方式与价格约束。

## 2. 不可变身份

- 标的：`588080.SH`；
- 信号基线：`baseline_20260901`；
- 信号基线SHA-256：`711254af3fe951cc0eb32c81121ef52233a0cf2577f46b14683b2f3e6b961993`；
- 执行规则来源：`experiments/0902_EX02/artifacts/frozen_execution_policy.json`；
- 执行规则版本：`execution_policy_20260902`；
- 入场价格上限：T日收盘价，向下取整到0.001元；
- 异常低开提示：T日收盘价乘以`1 - 0.006797902176638775`，向下取整到0.001元。

执行规则注册表解析时校验版本、文件哈希、来源文件哈希、标的和信号基线身份。任一身份不一致即停止。

## 3. 回测行为

回测入口保持通用：

- 任意标的始终生成`活动基线·次日开盘`、`BuyHold`和`MA5/MA20`；
- 当活动执行规则与本次标的和信号基线完全匹配时，额外生成`活动基线·执行规则`；
- 执行规则使用日线与30分钟线模拟入场触价，离场沿用优先次日开盘成交模型；
- 每个窗口独立配置初始资金，并使用窗口开始前已知目标仓位确定首日状态；
- 报告统一比较最大回撤、卡玛比率、盈亏比、收益率和夏普率；
- 额外输出执行规则订单和净值CSV；图表继续展示信号基线理论成交，避免把两种成交口径叠加在同一图中造成误读。

回测清单记录执行规则版本、哈希与是否应用。未匹配到活动执行规则属于正常通用路径。

## 4. 日频建议入口

命令：

```powershell
czsc-trader advice run --symbol 588080.SH --asset etf --actual-position 0 --quantity 50000
```

输入约束：

- `actual-position`必填，只允许`0`或`1`；
- `quantity`为正整数且符合ETF 100份整数倍；
- 只接受与活动执行规则身份匹配的标的和信号基线；
- 行情必须通过现有清单和三周期一致性校验。

输出字段：

- 信号日期、数据截止日、目标仓位、明确输入的实际仓位；
- 状态：`CASH`、`PENDING_ENTRY`、`HOLDING`、`PENDING_EXIT`；
- 动作：`WAIT`、`BUY`、`HOLD`、`SELL`；
- 建议数量、委托类型、价格约束、异常低开提示、有效期；
- 活动信号基线和活动执行规则的版本及哈希；
- 操作说明与明确的成交确认约束。

四种决策：

| 目标仓位 | 实际仓位 | 状态 | 建议 |
|---:|---:|---|---|
| 0 | 0 | `CASH` | `WAIT` |
| 1 | 0 | `PENDING_ENTRY` | 限价买入，最高价为T日收盘价 |
| 1 | 1 | `HOLDING` | `HOLD` |
| 0 | 1 | `PENDING_EXIT` | 优先卖出；预挂限价使用券商显示的合法价格下限，连续竞价可用五档即成转限价并设置保护限价 |

建议的有效期为下一交易日当日。系统不预测未来交易日日期，输出`NEXT_TRADING_SESSION`，从而避免自行维护不完整的节假日日历。

## 5. 状态与安全边界

- 建议命令无状态，不读取或改写账户账本；
- 实际仓位完全来自命令行显式输入；
- 未收到明确成交回报时，调用者继续传入原实际仓位；
- 程序不连接券商、不自动下单、不推断成交；
- 当日盘中价格只可作为执行风险观察，不改变收盘后生成的信号。

## 6. 错误处理

- 活动执行规则、来源文件或信号基线哈希不一致：失败；
- 标的、资产类型或基线不匹配：建议入口失败；
- 数据为空、未校验或缺少三个周期：失败；
- 实际仓位不为0/1、数量不符合ETF交易单位：失败；
- 最新目标信号不可计算：失败；
- 通用回测未匹配活动执行规则：保留三策略结果并记录未应用原因。
