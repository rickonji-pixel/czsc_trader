## 标准研究工作流

### 1. 明确研究问题

每轮只解决一个可陈述的问题，例如“改善range阶段的回撤和交易质量”。预先写清：

- 挑战对象和策略发布哈希；
- 可调整参数与保持冻结的部分；
- 数据截止日和评估窗口；
- 候选生成方法、数量和随机种子；
- 用户已批准的硬约束；
- 只用于解释的诊断指标。

未经用户批准的阈值保持诊断性质，不得临时升级为淘汰条件。收益、回撤、卡玛和盈亏比
出现取舍时，由证据和研究目标共同解释。

### 2. 创建不可变实验

新实验使用`experiments/策略ID/YYYYMMDD_策略ID_EXnn/`编号。同一策略同一天从`EX01`
开始递增，例如`experiments/S002/20260909_S002_EX02/`。历史实验ID保持原样，并统一归入
所属策略目录。目录契约见[实验档案说明](../experiments/README.md)。实验内部建议结构：

```text
01_goal.md                 研究问题和成功口径
02_design.md               数据、候选、窗口和评估协议
03_execution.md            实际运行、偏差和故障
04_conclusion.md           结论、限制和后续动作
run_experiment.py          本实验特有编排
artifacts/                 冻结输入、候选台账和机器证据
experiment_manifest.json   受管文件及哈希
```

单次实验只保留专属参数和编排。预计被两个以上实验复用，或进入正式运行链路的能力，放入
`src/czsc_trader/`；策略评估规则内聚到SE。完成并生成有效manifest后，实验保持只读。
发现错误时保留原实验，在新编号中修正并说明继承关系。

### 3. 冻结候选全集

先生成候选payload、参数、来源、种子和候选ID，再执行排名。无论候选在哪一环节退出，
都必须留下去向：输入无效、快速筛除、正式筛除、进入排名、Pareto层级、临时冠军或体检
失败。候选数量、失败数量和各阶段数量应能闭合。

历史实验产物可以作为缓存复用，前提是协议显式声明来源实验，并验证输入、实现版本和
制品哈希。缓存命中与现场计算分别记录；冠军重复性等关键审计继续现场执行。

### 4. 由TDR统一生成评估事实

TDR负责数据加载、因子、regime、完整策略执行和回测事实。研究脚本调用通用能力，避免
复制正式策略或执行逻辑。所有候选使用一致的：

- 完整收盘数据和因果时序；
- 100份交易单位、冻结费率和价格精度；
- 策略内嵌的唯一执行规则；
- 初始资金、窗口定义和指标语义；
- 未成交、部分成交和累计成交处理方式。

信号收益只能用于解释。候选PK和冻结必须使用完整执行口径，避免产生“策略参数 × 执行
规则版本”的组合空间。

研究统一读取`data/raw/`受控研究池。普通策略回看使用`data/backtest/`，其更新与研究池
相互独立。候选通过完整payload解析为候选策略快照，正式策略通过SM解析为发布快照；两者
进入同一确定性回放核心。每个窗口都显式传入起止日和独立初始现金，多窗口由实验编排，
不读取命名窗口配置。当前回测成交模型只支持完整成交或未成交，不模拟部分成交。

### 5. 由SE完成统一评估

新研究默认使用`opc-v3`，流程为：

```text
完整候选台账
  → 快速筛劣
  → 多窗口正式非劣判断
  → Pareto分层和排名
  → 唯一临时冠军
  → 工程、压力及统计稳健性体检
  → RECOMMEND_FREEZE / KEEP_INCUMBENT
```

核心比较优先级为最大回撤、卡玛比率和盈亏比，收益率用于判断收益代价和经济意义。
负卡玛窗口采用相对在位策略的非劣判断，同时披露改善幅度，避免微小噪声被包装为优势。
SE输出筛选、排名和审计证据，不直接改变SM或PTE状态。

首个策略候选没有在位冠军时，以同标的BuyHold作为第一个明确对手。PK只输出
`RECOMMEND_HEALTH_CHECK`，随后由SE独立汇总原有工程、压力和统计审计项执行冻结前
体检。PK结果不能直接充当冻结建议。

统计稳健性体检至少解释：

- CSCV/PBO：搜索结果落到样本外劣势的风险；
- Deflated Sharpe：考虑多重试验后的超额表现可信度；
- 配对平稳区块Bootstrap：临时冠军相对在位策略的方向稳定性；
- 真实候选邻域：最优点位于稳定平台还是孤立尖峰；
- 成本、滑点、成交和重复性压力：策略优势是否依赖脆弱执行假设。

`FAVORABLE/MIXED/WEAK`是风险披露标签。它与工程审计结论、核心指标、经济逻辑和样本量
共同支持人工判断，不单独充当自动否决线。

### 6. 人工确认并冻结

只有唯一临时冠军通过既定体检、相对在位策略具有足够实际意义时，SE才建议冻结。研究者
先审阅一页摘要、筛除台账和统计证据，再由人工执行接受：

SM冻结接口强制要求SE生成的冻结前体检批准书，并校验策略ID、候选ID、候选哈希、来源
哈希和`RECOMMEND_FREEZE`裁决。CLI缺少批准书时直接拒绝，避免人工操作跳过流程关口。

```powershell
.\.venv\Scripts\czsc-trader.exe strategy evaluate --experiment YYYYMMDD_SXXX_EXnn
.\.venv\Scripts\czsc-trader.exe strategy accept-evaluation `
  --experiment YYYYMMDD_SXXX_EXnn --actor tomxiao --reason "确认冻结并进入模拟盘"
```

接受操作创建新的不可变策略版本并登记证据，随后在PTE创建绑定该发布的独立虚拟账户。
冻结和模拟盘激活必须保持幂等；部分完成时记录可重试状态，不能生成重复版本。

### 7. 前瞻观察与后续晋升

冻结后的新增信号、订单和成交进入该版本的前瞻观察。PTE负责运行记录和绩效，SM负责
里程碑证据与资格。模拟盘记录不能自动证明策略有效，也不能自动触发实盘晋升。

PTE虚拟账户页的“前瞻观察”默认显示选择截止日前60个交易日作为行情背景，并显示截止
日后的全部完整日线、账户信号、订单意图、明确成交、目标持仓和实际持仓。红线左侧用于
理解策略所处环境，右侧才是该版本的前瞻记录；图表内容绑定账户的策略版本、发布哈希和
`selection_data_cutoff`。

如果前瞻数据被用于再次调参，它从该时刻起成为新版本的开发数据。旧版本的历史观察记录
仍然有效，新候选必须采用新的选择截止日、策略版本和前瞻起点，不能继续把已参与选择的
区间称为新候选的样本外。

## 数据集治理

### 开发池、内部验证和前瞻观察

- **开发池**：研究者已经查看、比较、调参或用于接受决策的数据。截止日与具体策略绑定，
  以对应`research/<策略ID>/HANDOFF.md`及冻结版本中的`selection_data_cutoff`为准。
- **内部验证**：开发池内的年度窗口、滚动窗口、留一窗口和walk-forward。它们用于检验
  跨周期稳定性，但仍属于开发证据。
- **前瞻观察**：某策略版本完成选择之后才出现、且未反向参与该版本选择的数据。它用于
  观察外推表现和运行可靠性。

“测试集”不是永久标签，而是相对于某个明确版本和选择时点的身份。2026年M1–M8曾参与
候选比较，因此对`S001-v2`属于开发池；把它换个名称或只看一次，都不能恢复独立性。
查看PTE图表本身不会污染数据。研究者一旦依据截止日后行情修改参数、筛选候选或决定
接受，相关区间即进入新版本的开发池；新版本必须登记新的选择截止日并重新开始前瞻观察。

### 数据污染检查

结论发布前逐项确认：

1. 候选生成、阈值修改、窗口选择和人工挑选是否看过所谓测试区间；
2. 同一批结果是否被多轮筛选，却只报告最后一次比较；
3. regime、因子、复权和执行价格是否严格使用当时可得数据；
4. 前瞻表现是否被用于修改同一策略后仍拼接展示；
5. 多个高度相关候选是否被当作一次普通比较；
6. 少量交易产生的高卡玛或盈亏比是否被过度解释。

发生污染时直接将相关区间归入开发池，更新选择截止日并创建新版本。保留旧实验及污染
说明，禁止删除不利结果或回写历史档案。

## 研究与评估的关键问题

- **因果时序**：T日完整收盘信号只能驱动后续交易日执行，regime也必须使用滞后数据。
- **分钟证据**：分钟K线数量、同日拆单和同一行情过程内的重复信号不等于独立样本；分钟
  策略按独立交易事件和交易日聚类审计。S003当前研究口径采用滚动60交易日：独立闭合
  事件数中位数目标12—20、P10至少8，每个机制每天最多一笔；前瞻观察仍需结合实际事件
  数、相关性、收益区间和市场状态判断，事件数量本身不能自动验证策略。
- **执行一致性**：研究、正式回测、TDR建议和PTE订单共享同一策略内嵌执行语义。
- **指标语义**：最大回撤使用负值表达；盈亏比只统计闭合交易，无有效样本时明确为N/A。
- **收益之外的代价**：优先观察回撤、卡玛和盈亏比，并披露换手、短亏、成交率及收益损失。
- **搜索偏差**：候选越多，偶然冠军概率越高；必须保留全集、做多窗口和统计稳健性审计。
- **平台优于尖峰**：邻近参数共同良好比单点第一更可信，但平台证据仍不能替代前瞻观察。
- **相对改善需有幅度**：形式上非劣但改善极小的候选通常缺乏实际意义，应在人工评审说明。
- **审计事实分层**：信号、订单意图、渠道受理、部分成交和全部成交分别记录；受理不等于成交。
- **范围控制**：研究目标之外的诊断只报告，不在结果已知后增加硬约束。
- **可复现性**：数据清单、候选、代码、协议、随机种子、产物和接受记录都进入哈希链。

## 启动一轮研究

1. 从[研究项目索引](../research/README.md)进入对应策略交接文件；
2. 核对策略身份、参考版本或种子、标的、研究问题和开发截止；
3. 使用`YYYYMMDD_策略ID_EXnn`创建新实验并在结果产生前冻结协议；
4. 复用TDR完整执行事实和SE评估能力，保留候选全集及全部筛除去向；
5. 对唯一临时冠军审阅统计风险、参数邻域、交易样本和收益代价；
6. 没有具备实际意义的胜者时保留当前状态，不为完成实验而冻结；
7. 人工接受胜者后由SM创建并冻结版本，再为其建立独立PTE虚拟账户。

研究开始前的最小检查：

```powershell
git status --short --branch
$StrategyId = "S002"
$ResearchSymbol = "510500.SH"
.\.venv\Scripts\czsc-trader.exe data validate --symbol $ResearchSymbol
.\.venv\Scripts\czsc-trader.exe strategy show --strategy $StrategyId
.\.venv\Scripts\czsc-trader.exe strategy validate --all
.\.venv\Scripts\czsc-trader.exe archive validate --all
```

- 正式策略身份与资格：`strategies/`；
- 各研究线当前上下文：`research/`；
- S001既有版本的历史规则依赖：`strategies/dependencies/legacy_rule_baselines/`；

  分离管理；
