# Strategy Evaluator 多核与算法加速设计

## 1. 背景与目标

EX04在8核16线程、128GB内存的本机上串行评价1,187项方案耗时约24分钟。OPC版本变化
会改变快速筛选结果，使此前未进入正式阶段的候选需要补做完整执行规则回测；因此不能
只重排旧正式短名单。

本次暂停EX05研究，先优化Trader的候选评价运行器。目标是在不改变候选、指标、筛选、
排名和审计语义的前提下，通过算法优化、历史实验证据复用和多核执行共同缩短大候选集
评价时间，并保持旧实验默认串行兼容。

## 2. 方案选择

采用四层组合方案：

1. 预计算并复用不可变的行情、标准化因子、窗口索引和制度分类；
2. 分块批量计算候选评分与目标仓位，并按实际交易行为去重；
3. 只读复用通过身份和哈希校验的历史实验指标；
4. 对仍需计算的唯一交易行为使用`joblib/loky`多进程并行。

主进程负责证据复用、候选批量评分、全局行为去重、任务分块、结果排序、筛选、排名和
文件发布。子进程只计算分配给自己的唯一行为块并返回不可变交易结果。逐候选进程任务
会放大序列化和调度成本，本轮不采用。

本轮不使用近似算法、指标抽样或提前终止劣质候选。所有候选仍须形成完整筛选审计；
优化只能消除重复工作或采用经串行参考验证的等价计算。

## 3. 配置与兼容

候选清单新增可选字段：

```json
{
  "evaluation_workers": 8
}
```

字段缺失时固定使用`1`，保证历史实验与现有调用保持串行。字段只接受正整数；EX05在
正式运行前基准测试`1、2、4、8`，把实测最快的多核值写入候选清单并进入输入哈希。
已归档候选清单不根据运行机器自动改写进程数。

根包显式声明`joblib>=1.5,<2`依赖，不依赖偶然的传递安装。

候选清单再新增可选字段`reuse_experiment_artifacts`和`reuse_source_experiments`，缺失时分别
固定为`false`和空列表以兼容历史实验。EX05显式启用复用并只声明`0903_EX04`为来源。
复用器不会扫描或猜测其他实验，也不启用`state`目录下的隐式缓存。

## 4. 算法优化边界

评价运行器一次性构建只读的`EvaluationWorkspace`，包含对齐后的价格数组、标准化因子
矩阵、窗口切片、日线收盘价，以及按参数身份复用的制度分类。子进程通过joblib自动
内存映射读取大数组，不分别生成行情和因子。候选循环不再复制完整因子DataFrame或
重复计算与候选无关的数据。

评分计算按固定大小的候选块执行。批量实现必须保持现有分组求和顺序；任何阈值附近
无法证明等价的候选退回现有逐候选评分路径。批量与参考路径生成的目标仓位必须逐元素
完全相同，之后才允许进入交易计算。

主进程收齐全部目标仓位后，以目标仓位字节、执行规则身份、费用场景和窗口身份生成
`behavior_key`并进行全局去重。相同key只执行一次交易模拟和权益计算；指标结果映射回
所有对应候选。因子事件、无前瞻审计、制度区间目标等候选专属信息仍分别生成和验证，
不能因交易行为相同而省略。

数组化优先消除DataFrame复制、反复索引和重复窗口归一化，不在本轮替换已冻结的交易
语义。现有串行路径保留为正确性参考实现。

## 5. 历史实验证据复用

历史实验产物是唯一复用来源，不建立`state/evaluation_cache`。复用器只读取当前清单明确
声明、状态完整、审计文件存在且哈希验证通过的实验目录，也不修改来源实验。

单项结果的`evaluation_key`由以下身份共同确定：

- 行情数据内容哈希和开发截止日期；
- 完整策略参数与执行规则哈希；
- 窗口起止日期、评价层级和费用场景；
- 评价指标口径版本与回测引擎身份。

OPC筛选或排名协议不进入`evaluation_key`，因为它只消费底层指标。协议变化可以复用相同
底层评价，并仅补算此前没有产生的层级、窗口或场景。旧实验若无法从冻结清单、协议和
产物重建完整key，则视为未命中，不能推测复用。

当前实验最终仍发布完整指标文件，并额外发布`artifact_reuse.csv`，逐项记录
`evaluation_key`、来源实验、来源文件哈希和`REUSED`或`COMPUTED`状态。这样当前实验可
独立解释，同时保留完整来源链。明确要求独立重复验证的实验把
`reuse_experiment_artifacts`设为`false`并强制重算。

## 6. 并行边界

`CandidateEvaluationContext`增加`workers: int = 1`。公开的
`evaluate_candidate_payloads`保留现有签名与返回类型，根据候选数量选择串行核心或
并行包装：

- `workers=1`或候选少于32项时走原串行核心；
- 候选不少于32项且`workers>1`时，切成最多`workers`个连续非空块；
- 每个块只接收本块的候选payload与候选ID，避免反复复制完整7.6MB候选清单；
- `loky`子进程内部限制数值库线程数为1，防止进程与BLAS双重超配；
- 结果按块序和块内原始顺序合并，输出顺序与串行完全相同。

正式短名单、压力测试和重复运行通常少于32项，继续串行，避免多进程启动成本抵消收益。

## 7. 确定性与审计

相同研究输入的参考、优化、串行、并行和复用路径必须满足：

- `MetricObservation.to_dict()`逐项完全相等；
- 候选、场景和窗口顺序完全相同；
- 筛选去向、Pareto排名、冠军、业务结论和规范化指标哈希相同；
- 冷启动计算与历史产物复用得到的完整评价结果完全相同；
- 子进程不创建、修改或删除任何研究文件。

`evaluation_workers`和复用开关属于执行审计信息，会使整体输入身份与基准文件哈希不同；
它们不进入单项`evaluation_key`，也不改变规范化指标哈希。

EX05新增`artifacts/parallel_benchmark.json`，保存机器CPU信息、joblib版本、候选ID集合、
进程数选择、每档耗时、加速比、串并行等价结论和最终选择。该文件只决定运行配置，
不参与策略优劣判断。

## 8. 失败与恢复

任一子进程异常时，整次runner调用失败并向上抛出原始异常。评价服务在所有阶段完成前
不发布`evaluation_result.json`，所以失败不会形成可误读的完整结论。已有原子文件发布
机制保持不变。

无效`evaluation_workers`在回测开始前失败。并行失败不会自动静默退回串行，因为静默
切换会掩盖环境问题并使实际运行配置与审计不一致；操作者可显式把清单改为1后重新生成
新的输入身份。

复用来源只要缺少身份字段、文件或哈希校验失败，就对对应单项按未命中处理并重新计算；
来源实验存在损坏迹象时同时写入诊断记录。当前实验不会因旧产物不可复用而发布部分结论。

## 9. 基准方法与验收

从EX05预注册候选清单中排除在位策略，将剩余候选按ID排序；对`k=0..63`选择索引
`floor(k * (N - 1) / 63)`，得到覆盖完整ID范围的固定64项代表候选。在相同SCREENING
窗口上依次测试以下路径：现有串行参考、算法优化单进程，以及算法优化后的2、4、8进程。
每档只运行一次；现有串行结果作为正确性基准。基准记录因子准备、评分与仓位、唯一行为
交易模拟、候选审计和产物组装各阶段耗时，以及候选数、唯一行为数和复用命中数。
多核选择规则为：

1. 排除与串行结果不完全一致的配置；
2. 排除相对现有串行参考路径端到端加速低于3.0倍的多核配置；
3. 在剩余多核配置中选择耗时最短者；
4. 若耗时差小于5%，选择进程数较少者。

功能验收要求相关单元测试、静态检查和编译通过。冷启动性能按无历史产物复用计算；
完全热启动要求本轮所需单项均可从历史实验命中，部分热启动单独报告命中率和补算耗时。

性能验收标准为：

- 冷启动同规模完整筛选不超过5分钟，即相对EX04约24分钟达到至少4.8倍端到端加速；
- 完全热启动不超过1分钟；
- 至少一个多核配置与算法优化组合后达到3.0倍端到端加速；
- 若冷启动超过5分钟，暂停EX05并根据分阶段计时继续优化；
- 若所有多核配置低于3.0倍，优先分析进程初始化、数据加载、序列化、任务粒度和内存带宽。

本机历史`joblib`任务在8进程下已达到约2.77倍，因此1.5倍无法证明本实现充分利用了
8个物理核心。冷启动5分钟是算法与并行组合后的交付目标；单独报告优化单进程和多核
增量加速，用于诊断各层贡献，但不要求已经优化后的单进程再获得3.0倍并行加速。理论
8倍线性加速不作为验收条件。

## 10. 文件边界

- `pyproject.toml`：声明joblib运行依赖。
- `src/czsc_trader/candidate_evaluation.py`：参考路径、工作区、批量评分、行为去重、连续分块
  和loky并行包装。
- `src/czsc_trader/evaluation_artifacts.py`：评价身份、历史实验查找、哈希验证和复用记录。
- `src/czsc_trader/application/evaluation_service.py`：读取并验证执行配置，合并复用和新计算结果。
- `tests/test_candidate_evaluation.py`：批量等价、行为去重、分块、串并行等价与无效配置测试。
- `tests/test_evaluation_artifacts.py`：身份失效、哈希验证、部分命中和完整来源链测试。
- `experiments/0903_EX05/benchmark_parallel.py`：固定64项性能基准与JSON证据。
- `experiments/0903_EX05/run_experiment.py`：读取已选进程数并生成固定候选清单。
- `docs/DEVELOPMENT_HANDOFF.md`：记录并行配置、兼容边界和排障入口。

## 11. 非目标

- 不修改OPC-v1或OPC-v2规则；
- 不改变策略、信号、执行规则、费用或数据窗口；
- 不并行写研究产物；
- 不自动冻结策略；
- 不建立独立运行时缓存；
- 不实现近似筛选、提前终止、分布式计算或GPU计算。
