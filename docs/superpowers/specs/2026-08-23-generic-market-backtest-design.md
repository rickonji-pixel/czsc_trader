# A股股票与 ETF 通用数据准备及固定基线回测设计

## 背景

项目当前围绕 `588080.SH` 构建：`src/czsc_trader/data.py` 固定加载 `588080` 的 2024—2026 年 30分钟、日线和周线文件，`scripts/run_research.py` 执行候选规则研究并输出 `selected_rule.json`。底层已有 vectorbt 回测函数，但没有面向任意标的、只使用固定规则且不进行候选搜索的独立回测入口。

本次改造支持使用项目现有 `dataflows` 与 Tushare 数据源，为 A股股票和 A股 ETF 准备并验证行情，然后使用已冻结的最新规则基线回测任意标的。研究、基线晋升、数据准备和固定规则回测必须保持独立职责。

## 目标与非目标

### 目标

1. 通过命令行获取指定 A股股票或 ETF 的 30分钟、日线和周线行情。
2. 将行情写入现有扁平目录 `data/raw`，保持 `<证券代码>_<周期>_<年份>.csv` 命名。
3. 在行情投入使用前完成结构、交易时段、跨周期和文件哈希验证。
4. 冻结 `outputs/588080_0823_R06/selected_rule.json` 为首个不可变规则基线。
5. 提供独立的固定规则回测入口，可通过参数选择任意证券代码。
6. 默认使用注册表中的最新规则基线，同时允许显式选择历史基线。
7. 保留历史结果的可复现性，并继续使用 `<证券代码>_<MMDD>_RXX` 输出目录。

### 非目标

1. 本次不把候选搜索研究泛化到任意标的，也不改变现有研究选优逻辑。
2. 不支持港股、美股、期货或非 A股市场。
3. 不在回测过程中隐式联网、刷新或改写行情。
4. 不因研究结果达到 PASS 而自动更新规则基线。
5. 不把 588080 的收益目标默认套用到其他标的。

## 四类职责

```text
研究候选 → 人工确认 → 冻结为版本化基线 → 固定规则回测
                         ↑                 ↑
                    显式晋升操作      已验证行情快照
                                           ↑
                                  独立数据准备命令
```

### 研究

`scripts/run_research.py` 继续负责候选规则生成、等价仓位去重、候选排序和规则选择。研究产物可以包含 `candidate_results.csv` 与 `selected_rule.json`，但不能自动修改规则基线。

### 基线晋升

基线晋升是独立、显式操作。它验证来源规则，分配新版本，复制不可变规则文件，更新注册表。只有用户明确确认后才执行。

### 数据准备

`scripts/prepare_market_data.py` 负责联网获取、标准化、验证和落盘。其成功产物是回测唯一可接受的数据输入。

### 固定规则回测

`scripts/run_backtest.py` 读取已经验证的数据和已经冻结的规则，不遍历候选空间、不选择参数、不更新基线。

## 规则基线

### 目录和文件

```text
configs/rule_baselines/
├── baseline_v001.json
└── registry.json
```

`baseline_v001.json` 是 `outputs/588080_0823_R06/selected_rule.json` 的冻结副本，规则内容保持不变。注册表保存：

- `latest`：当前默认基线版本；
- 各版本对应的文件名；
- 来源研究目录；
- 冻结时间；
- 规则 SHA-256；
- 策略标识；
- 所需数据频率。

基线文件一旦登记便不可原地修改。新规则只能新增 `baseline_v002.json`、`baseline_v003.json` 等版本。更新 `latest` 不改变已有回测结果，因为每次回测都会复制实际规则并记录版本及哈希。

### 基线解析

回测未传 `--baseline` 时读取 `registry.json` 的 `latest`。传入 `--baseline baseline_v001` 时解析指定历史版本。解析器必须验证：

1. 注册表中存在该版本；
2. 文件存在且是合法规则对象；
3. 文件哈希等于注册表记录；
4. 权重、阈值、确认天数、最短持仓和门控值满足现有 `Rule` 约束。

任一条件失败都终止回测。

## 数据准备接口

典型命令：

```powershell
python scripts/prepare_market_data.py `
  --symbol 600519.SH `
  --asset stock `
  --start 2024-01-01 `
  --end 2026-08-21

python scripts/prepare_market_data.py `
  --symbol 510300.SH `
  --asset etf `
  --start 2024-01-01 `
  --end 2026-08-21
```

参数约束：

- `--symbol` 必须是带交易所后缀的完整 Tushare 代码；
- `--asset` 必须明确为 `stock` 或 `etf`，不依赖代码前缀自动推断；
- `--start` 和 `--end` 均为包含边界的日期；
- 仅接受 `.SH` 和 `.SZ` 的 A股代码；
- 默认数据目录为 `data/raw`，可通过 `--data-dir` 覆盖。

`dataflows.tushare_stock` 和 `dataflows.tushare_etf` 增加稳定的公开 DataFrame 获取接口。命令不解析现有文本报告，也不直接依赖以下划线开头的私有函数。

## 扁平数据布局

继续使用现有布局：

```text
data/raw/
├── 600519_30m_2024.csv
├── 600519_daily_2024.csv
├── 600519_weekly_2024.csv
├── 600519_manifest.json
├── 600519_validation.json
├── 510300_30m_2024.csv
├── 510300_daily_2024.csv
├── 510300_weekly_2024.csv
├── 510300_manifest.json
└── 510300_validation.json
```

CSV 沿用项目当前输入字段：

- 30分钟：`datetime,open,high,low,close,volume,amount`；
- 日线和周线：`date,open,high,low,close,volume,amount`；
- CSV 使用 `utf-8-sig` 编码；
- 文件按时间升序，每个时间戳唯一；
- 按自然年拆分，仅写入实际存在数据的年份。

`manifest.json` 至少记录完整证券代码、证券类型、数据源、请求区间、实际覆盖区间、各频率行数、首尾时间、每个 CSV 的 SHA-256、生成时间及依赖版本。

`validation.json` 记录逐项验证状态、统计值和最终 `PASS`。只有最终状态为 `PASS` 的清单才能被通用加载器读取。

## 数据验证

### 单表验证

每个频率都必须满足：

1. 非空且包含全部必需列；
2. 时间戳可解析、严格递增且不重复；
3. OHLC、成交量和成交额为数值且无空值；
4. 价格为正，成交量和成交额非负；
5. `high >= max(open, close)`、`low <= min(open, close)` 且 `high >= low`；
6. 实际证券代码、证券类型和请求参数一致。

### 30分钟交易时段验证

完整交易日必须正好包含以下 8 个收盘时间：

```text
10:00 10:30 11:00 11:30 13:30 14:00 14:30 15:00
```

数据准备过程丢弃尚未结束的实时 K 线，但请求区间内的历史交易日不得残缺。发现重复、异常时刻或少于 8 根历史 K 线时验证失败。

### 跨周期验证

1. 30分钟按交易日聚合后的 OHLC 必须与日线一致；
2. 成交量与成交额按 `dataflows` 既定单位归一化后，在规定相对误差内与日线一致；
3. 日线按 `W-SUN` 周期聚合，周日期取该周最后一个实际交易日；
4. 聚合后的周线 OHLC、成交量和成交额必须与周线数据一致；
5. 三个频率的实际覆盖区间和缺口写入验证报告。

跨周期价格容差和成交量、成交额相对容差使用具名常量，并写入 `validation.json`，不得静默放宽。

### 安全落盘

新数据先写入同一磁盘上的临时目录，在临时目录内完成全部验证和哈希计算。全部通过后才替换该证券代码对应的正式 CSV、清单和验证报告。替换失败时恢复旧文件，不能留下新旧文件混合且清单仍为 PASS 的状态。验证失败时不改写任何现有正式文件。

Tushare token 只从现有环境配置读取，禁止写入日志、清单、报告或 Git。

## 通用数据加载器

`load_market_data` 改为接收 `symbol`，不再依赖全局 `SYMBOL`、固定年份或固定文件名。加载流程为：

1. 规范化完整证券代码并取得六位代码；
2. 读取 `<代码>_manifest.json` 和 `<代码>_validation.json`；
3. 要求验证状态为 `PASS`；
4. 按清单列出的文件读取，而不是假定固定年份；
5. 重新计算文件哈希并与清单核对；
6. 规范化为 `dt,symbol,open,high,low,close,vol,amount`；
7. 再执行项目侧单表及跨周期验证；
8. 返回带 `symbol`、`asset_type`、覆盖区间、哈希和清单信息的 `MarketData`。

现有 588080 数据需要生成兼容清单，确保当前研究入口和历史测试继续工作。研究入口仍默认使用 `588080.SH`，其行为和收益验收目标不因本次改造变化。

## 固定规则回测入口

典型命令：

```powershell
python scripts/run_backtest.py `
  --symbol 600519.SH `
  --asset stock `
  --start 2024-01-01 `
  --end 2026-08-21
```

可选指定历史基线：

```powershell
python scripts/run_backtest.py `
  --symbol 510300.SH `
  --asset etf `
  --baseline baseline_v001
```

参数规则：

- `--symbol` 和 `--asset` 必填，并必须与数据清单一致；
- `--baseline` 缺省时使用注册表中的 `latest`；
- `--start`、`--end` 可选，未提供时使用全部已验证数据；
- 只提供一个日期边界时，另一边使用数据实际边界；
- `--fee-rate` 默认 `0.0005`，`--init-cash` 默认 `1000000`；
- 默认数据目录为 `data/raw`，默认输出根目录为 `outputs`。

回测必须先生成 CZSC 因子，再把固定 `Rule` 应用于因子序列，得到全历史目标仓位。固定规则应用逻辑从候选选择编排中提取为可复用函数；回测入口不得调用候选遍历、排序或选优函数。

交易继续遵循：因子日 T 只读取截至 T 日收盘的数据，目标仓位最早在下一交易日开盘执行，只做多或空仓，计入单边费用，并由 vectorbt 和独立账本交叉复算。每笔订单必须关联因子事件并通过无前视审计。

## 回测区间与可选验收目标

未传验收配置时，回测对 `--start` 至 `--end` 的单一区间运行；缺省日期使用全部有效数据。结果状态为 `N/A`，只报告指标，不判定 PASS/FAIL。

可通过 `--targets <json>` 传入多个具名验收区间。文件中每项同时定义 `start`、`end` 和 `min_return`。使用该文件时不得同时传 `--start` 或 `--end`，避免区间解释冲突。每个具名区间使用独立初始资金，并按绝对净收益门槛判断；所有区间均达到门槛才是总体 PASS。

验收目标只评价最终结果，不参与规则选择、不修改因子、不覆盖仓位，也不影响最新基线解析。

## 输出目录与产物

每次回测原子创建新目录：

```text
outputs/<证券代码>_<MMDD>_R<两位序号>/
```

证券代码不带交易所后缀，`MMDD` 使用 Asia/Shanghai 的执行日期，`RXX` 在同一证券代码和日期下从 `R01` 自动递增，绝不覆盖已有目录。例如：

```text
outputs/600519_0823_R01/
outputs/600519_0823_R02/
outputs/510300_0823_R01/
```

产物包括：

- `manifest.json`：证券、区间、数据哈希、基线版本和规则哈希、费用、资金、运行环境；
- `baseline_rule.json`：本次实际使用的完整冻结规则副本；
- `metrics.json`：收益、最大回撤、夏普、交易次数、持仓比例和可选验收状态；
- `orders.csv` 或具名区间的 `orders_<period>.csv`；
- `equity.csv` 或具名区间的 `equity_<period>.csv`；
- `factors.csv` 与 `factor_events.csv`；
- `audit.json`；
- `chart.html` 或具名区间的 `chart_<period>.html`；
- `report.md`。

HTML 延续当前已确认的交互行为：主图和副图共享悬停位置与信息；信息面板默认位于虚线左侧；因子入场图标为红色、离场图标为绿色；因子信号、策略买卖标记和 K 线避免相互遮挡。

回测产物不包含 `candidate_results.csv` 或新的 `selected_rule.json`，以便从文件层面也能区分研究和回测。

## 错误处理

以下情况必须以非零退出码终止，并给出可操作的错误信息：

- 行情文件、清单或验证报告缺失；
- 数据验证状态不是 PASS；
- 实际文件哈希与清单不一致；
- 证券代码或资产类型不一致；
- 请求区间没有有效交易日或缺少区间开始前的信号日；
- 最新基线不存在、规则非法或哈希不一致；
- Tushare 返回空数据、权限错误或网络错误；
- 无前视审计或独立账本复算失败；
- 同时传入互斥的日期区间与多目标配置。

失败的回测目录保留最小 `failure.json` 后停止，不伪造完整报告或 PASS 状态；数据准备失败则完全不替换正式数据。

## 测试策略

### 默认快速测试

1. 股票与 ETF 获取接口使用伪造 Tushare DataFrame，验证标准化和错误传播；
2. 30分钟时刻、每日 8 根、OHLC 关系及跨周期聚合验证；
3. 分年拆分、清单、哈希和失败不覆盖旧数据；
4. 通用加载器自动发现年份并拒绝被篡改文件；
5. 基线注册表解析、默认 latest、历史版本和哈希错误；
6. 固定规则回测不调用候选生成或排序；
7. 默认全区间、单边日期、多目标互斥和 N/A/PASS/FAIL 语义；
8. 输出目录按 `<代码>_<MMDD>_RXX` 递增；
9. 回测 manifest 固化实际基线和数据哈希；
10. 小型因果数据验证次日开盘执行、无前视审计和完整产物。

### 慢速与联网测试

- Tushare 实时测试标记为 `network`，默认不运行且不输出 token；
- 23,760 个候选的完整研究测试标记为 `slow`，默认快速测试排除；
- 修改候选生成、规则状态机或正式研究逻辑时显式运行慢速测试；
- 本次交付至少运行新增快速测试、现有相关回归测试和一个使用本地已验证数据的固定规则回测冒烟测试。

## 验收标准

1. `baseline_v001` 与 R06 规则内容一致，注册表哈希验证通过；
2. 股票和 ETF 都能通过同一数据准备入口生成扁平年度文件及 PASS 验证报告；
3. 数据损坏、跨周期不一致或基线篡改均能在回测前被拒绝；
4. `run_backtest.py` 可选择任意已准备的 A股股票或 ETF，并默认使用最新基线；
5. 固定规则回测不产生候选结果，也不改变注册表；
6. 未配置收益目标时状态为 N/A，配置目标时才计算 PASS/FAIL；
7. 输出目录和产物符合本设计，历史结果不被覆盖；
8. 现有 588080 研究流程及 R06 结果语义保持不变。
