# 研究设计

## 1. 冠军身份

正式执行只从 `configs/rule_baselines/registry.json` 解析活动冠军：

- 版本：`baseline_20260826`；
- 注册表规范SHA-256：`fc22ca5a973f77faf528cdb3efba4900163e18fe0c08cf79234d79ef22f5c822`；
- 源冻结对象：`experiments/0824_EX04/artifacts/frozen_challenger.json`；
- 源文件SHA-256：`c6fa86c0f87743564231dec4fb6e66971bde0fa4107829d077cb5cf31c53885f`。

任一身份不一致都必须以ERROR终止。

## 2. 固定动态仓位状态机

空仓时沿用冠军的入场确认；成立后目标仓位为 `1.0`。持仓未达到原最短持有期3日时维持全仓。达到最短持有期后：

- `score >= 0.175`：目标仓位 `1.0`；
- `0.025 < score < 0.175`：目标仓位 `0.5`；
- `score <= 0.025`：沿用原退出确认，目标仓位 `0.0`。

半仓状态在分数恢复至 `0.175` 时恢复全仓，跌至 `0.025` 时退出。没有新阈值、候选参数或回看优化。

目标变化于下一交易日开盘执行。`1 -> 0.5` 卖出、`0.5 -> 1` 买入均按执行前组合资产计算目标比例并支付手续费；仓位状态不变时不再平衡。

## 3. 可见样本诊断与冻结

可见样本截止 `2025-12-31`，展示 `2022H1` 至 `2025H2` 八个半年窗口。每个窗口与冠军逐窗口独立注资比较费后收益率，同时展示风险指标。因为挑战者唯一且状态规则已冻结，这一步不做候选选择；完整2021—2025路径直接写入 `frozen_challenger.json` 并计算SHA-256。冻结前不得加载2026数据。

## 4. 原冠军挑战验收

冻结后才加载2026数据，窗口保持原协议：

- `2026Q1`：2026-01-01至2026-03-31；
- `2026H1`：2026-01-01至2026-06-30；
- `2026M1-M8`：2026-01-01至2026-08-21。

挑战者费后收益率在三个窗口必须全部严格高于冠军才为PASS。夏普、最大回撤、名义持仓率、交易次数和变仓次数不参与判定。2026截至8月28日已经被观察，本轮仅保持既有协议可比性。

## 5. 因果与资金审计

- `Entry` 必须对应 `0 -> 1`；`Reduce` 对应 `1 -> 0.5`；`Increase` 对应 `0.5 -> 1`；`Exit` 对应正仓位 `-> 0`。
- 每笔订单连接唯一事件；信号日严格早于执行日，且执行日为下一交易日。
- 事件分数与冻结因子框架相同，事件前后仓位与目标路径精确一致。
- vectorbt与独立资金账本逐日一致；冠军二元路径身份完全一致。

## 6. 状态与归档

正常完成写PASS或FAIL；协议漂移、身份不一致、账本不闭合、因果审计失败或文件错误写ERROR，并如实记录冻结前后是否访问2026。普通回测outputs与隔离回放不作为研究证据。
