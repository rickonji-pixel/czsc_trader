# 研究设计

## 1. 冠军身份

正式执行从 `configs/rule_baselines/registry.json` 解析：

- 版本：`baseline_20260826`；
- 注册表规范SHA-256：`fc22ca5a973f77faf528cdb3efba4900163e18fe0c08cf79234d79ef22f5c822`；
- 源冻结对象：`experiments/0824_EX04/artifacts/frozen_challenger.json`；
- 源文件SHA-256：`c6fa86c0f87743564231dec4fb6e66971bde0fa4107829d077cb5cf31c53885f`。

任一身份不一致都必须以ERROR终止正式执行。

## 2. 挑战者动作

对冠军的冻结综合分数应用同一入场确认。入场确认成立的信号日：

- `score >= full_threshold`：目标仓位为 `1.0`；
- `0.175 <= score < full_threshold`：目标仓位为 `0.5`。

`full_threshold`候选固定为 `0.200、0.225、0.250`。一旦入场，目标仓位保持为该次入场值；分数随后升高或降低都不触发半仓与满仓互换。达到原最短持有期并满足原退出确认后，目标仓位变为 `0.0`。

信号日目标在下一交易日开盘执行。半仓买入只在入场执行日按执行前组合资产的50%计算股数；随后持股数量固定，不做每日比例再平衡。卖出时清空全部持股。手续费为单边 `0.0005`。

## 3. 选择

选择数据截止 `2025-12-31`。八个验证窗口为：

`2022H1、2022H2、2023H1、2023H2、2024H1、2024H2、2025H1、2025H2`。

每个候选与冠军逐窗口独立注资回测。候选按以下顺序稳定排序：

1. 收益率严格高于冠军的窗口数；
2. 最差窗口收益增量；
3. 收益增量中位数；
4. 平均收益增量；
5. 候选ID字典序。

候选ID固定为 `full_0.200、full_0.225、full_0.250`。夏普、最大回撤、名义持仓率和交易次数写入候选表，但不得进入排序。

排序第一的候选用完整2021—2025路径重建并写入 `frozen_challenger.json`。冻结文件落盘并计算SHA-256之前，正式运行器不得加载2026数据。

## 4. 原冠军挑战验收

冻结后才加载截至 `2026-08-21` 的数据，窗口保持：

- `2026Q1`：2026-01-01至2026-03-31；
- `2026H1`：2026-01-01至2026-06-30；
- `2026M1-M8`：2026-01-01至2026-08-21。

每个窗口中挑战者费后收益率必须严格高于冠军。三个窗口全部满足才为PASS；任一不满足即FAIL。风险指标完整展示但不参与判定。三个窗口已经被项目观察，本轮目的为保持原规则下的可比挑战，不声称重新获得独立性。

## 5. 因果与资金审计

- 每个入场或退出订单必须连接唯一因子事件。
- 信号日必须严格早于执行日，且执行日必须是下一交易日。
- 入场事件必须对应 `0 -> 0.5` 或 `0 -> 1.0`；退出必须对应 `0.5/1.0 -> 0`。
- 持有期间不得产生半仓与满仓之间的订单。
- vectorbt与独立逐笔权益账本必须逐日一致。
- 冠军二元路径与活动基线应用结果必须完全一致。

## 6. 状态与归档

正常完成时，策略判定写为PASS或FAIL。任何协议漂移、身份不一致、资金账本不闭合、因果审计失败或文件错误都写为ERROR，保存错误摘要并冻结档案，不把异常包装成策略FAIL。

固定产物和实现边界见 `docs/superpowers/specs/2026-08-29-position-sizing-experiment-design.md`。普通回测 `outputs`、运行时临时目录和回放副本不构成本轮研究证据。
