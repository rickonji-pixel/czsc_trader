# 策略研究交接

> 本文是策略研究领域的唯一总入口，用于跨机器、跨会话恢复研究工作。它维护研究批次索引、
> 当前标准工作流、数据与证据边界以及续作方法。具体策略的目标和当前结论读取
> `research/<策略ID>/HANDOFF.md`；不可变事实读取`experiments/`；正式身份与冻结版本读取
> `strategies/`。

开发环境、系统架构、测试规则和PTE运维见[开发运维交接](../docs/DEVELOPMENT_HANDOFF.md)；候选
交付结构见[策略候选包](../docs/CANDIDATE_PACKAGE.md)。本文同时维护研究所需的目录查询、数据、
回测、治理和档案校验入口。

## 研究批次与目标治理

每个`SXX`是稳定策略族ID；同一策略族可以开启多个研究批次，每个批次由独立SGC标识。
研究目标绑定具体批次，在对应策略族的`HANDOFF.md`维护当前意图，至少说明：

- 标的、资产类型、策略职责和需要证伪的金融假设；
- 开发池范围与截止日；
- 对手、收益目标、最大回撤、成本和仓位边界；
- 交易频率属于硬约束还是观察指标；
- 候选形成、PK、体检和停止研究的条件。

跨策略的用户偏好只能作为新批次立项目标的输入，不能自动成为全部策略的统一硬门。目标调整
从下一项预注册实验起生效；已经读取结果的区间属于开发证据，不能把事后调整包装成原始目标。
历史实验对旧`research/RESEARCH_MANDATE.md`的引用继续由Git历史和实验哈希解释，不回写实验
档案，也不影响当前工作流。

策略身份沿用以下层级：

```text
SXX 策略族 → SGC研究批次 → SXX-CXXX 研究候选 → SXX-vN 冻结版本
                                                        → SRT部署 → 独立授权PTE账户
```

同一批次可以形成多个候选，但只能按冻结时的完整证据创建不可变版本。冻结版本进入模拟盘后
禁止原地调参；任何公式或参数变化都必须形成新候选并重新走完整流程。

## 标准研究工作流

### 统一研究抽象：y=f(x)

完成态策略的本质，是一个在既定数据、成本和执行约束下满足研究目标的确定性函数
`y = f(x)`：

- `x`是决策时点因果可得的输入，包括行情、资金、宏观、事件及由其计算的因子和信号；
- `F`是尚未确定参数的策略原型，规定输入如何分工、组合、门控、退出和形成仓位；
- `f`是通过参数搜索、平台审查和代表点选择后，由`F`实例化得到的具体函数；
- `y`是`f(x)`产生的目标仓位、调仓决策或原子执行计划，收益率本身不是`y`，而是对完整
  执行结果的评价。

因此研究过程依次回答三个问题：基于金融假设和数据证据得到哪些有效输入`x`；选择或构造
哪一类有明确职责和失效模式的原型`F`；如何通过联合搜索找到满足目标的可行区域，并从稳定
参数平台中选择代表点形成最终`f`。FSC复用`x`的定义，STC复用`F`的结构，Search实例化`f`，
SRT计算`y`，TXE统一生成成交与账户事实，SE执行确定性数值审计，TDR在正式评审
节点复核目标、组织完整体检并作出机器裁决。

### 1. 回到第一性原理

新批次先回答四个问题，再开始信号搜索：

1. 标的是什么资产，收益由哪些经济机制和催化因素驱动；
2. 哪些解释互相竞争，分别能提出什么可证伪假设；
3. 证伪需要哪些数据，何时可得，是否存在修订或时点穿越；
4. 用户希望策略承担什么职责，愿意接受怎样的收益、回撤、成本、仓位和证据速度。

结论写入`research/SXX/HANDOFF.md`。节点一只登记可修订的ResearchIntent和研究方向，不把
早期目标升级为仓库级硬合同。单项实验仍应在读取结果前预注册该实验的问题、数据和裁决规则；
候选被人工批准进入冻结流程时，才以EvaluationMandate锁定最终目标、开发截止、证据已见边界、
主成本、对手、交易频率口径和强制体检项。被退回的候选通过同一SGC追加新送审印章；已冻结
或已失效批次必须开启新SGC，不得重写已有证据。机制
故事只用于提出假设，不能替代统计证据。

### 2. 创建不可变实验

实验目录采用`experiments/SXX/YYYYMMDD_SXX_EXnn/`，例如：

```text
01_goal.md                 研究问题和成功口径
02_design.md               数据、候选、窗口和评估协议
03_execution.md            实际运行、偏差和故障
04_conclusion.md           结论、限制和后续动作
run_experiment.py          本实验特有编排
artifacts/                 冻结输入、候选台账和机器证据
experiment_manifest.json   受管文件及哈希
```

实验ID全局唯一。完成并生成有效manifest后保持只读；发现错误时保留原实验，在新编号中修正
并声明继承关系。失败实验与不利结果同样保留。目录契约见
[实验档案说明](../experiments/README.md)。

单次实验只保存专属参数和编排。预计被两个以上实验复用，或进入正式运行链路的能力，进入
对应独立包；TDR只保留研究立项、冻结评审、正式冻结和版本维护等治理入口，不承载通用研究
算法，避免研究脚本复制生产逻辑或把能力包再次内聚到裁判员。

实验以“一个预注册决策问题”为单位，不以一次命令或一个统计量为单位。同一协议下可以连续
完成搜索、平台审计和预先定义的敏感性检查；只有假设、数据、原型、搜索合同、硬约束发生
变化，或下一步依赖已经看到的结果时，才创建新实验，避免为了留痕把研究切成大量碎片。

### 3. 普查并选择输入x

项目级FSC（Factor & Signal Catalog）位于`catalog/`，回答“项目已经有哪些信息族、因子和
信号定义”。研究批次通过`materials.json`绑定标的、数据和开发截止。FSC只复用定义；计算值、
缓存、收益和结论始终属于具体`SXX`。

因子与信号研究依次执行：

```text
FSC定义普查 → 标的内物化 → 技术质量过滤 → 去冗余
             → 职责互补选择 → 机制证伪 → 候选评价
```

技术过滤只处理数据质量、覆盖和状态密度，不能用收益提前筛定义。信息族选择必须解释金融
职责、时间尺度和重复信息，既避免只试单一信息族，也避免堆叠同族信号。

研究脚本可以直接使用tsfresh或其他合适的第三方库提取候选特征。所有结果标记为
`DEVELOPMENT_ONLY`，完成因果时序、去重和金融语义审查后才能登记FSC。引入新研究库无需先
修改TDR，但候选送审后必须按正式执行和审计口径独立复算。

### 4. 设计并审查策略原型F

完成输入`x`后，从STC（Strategy Template Catalog）选择少量有机制依据的策略函数模板`F`。
在读取组合收益前，必须形成输入职责矩阵，说明每个信息族承担机会、风险、确认、退出或仓位
中的哪一项职责，并检查同一信息是否在基础分和门控中重复使用。模板同时记录参数边界、已知
失效模式、目录摘要和确定性实例ID；实例化只证明结构合法，不构成Alpha证据。

原型进入搜索前执行低成本可行性检查：全部输入在决策时点因果可得，未来能够稳定增量获取，
候选实现能够产生完整决策，SRT与TXE能够表达数据、成交和账户语义。参数搜索前必须明确
`StrategyImplementation`的输入契约、交易日历范围、计算范围和渠道无关输出；搜索、回测与
正式复核复用同一策略实现。节点二送审前必须完成候选SRT及源码绑定。该检查只暴露数据或
工程阻断，不参与Alpha判断，也不要求提前建设PTE部署。

策略实现负责推导初始信号日和回看数据窗口。研究脚本、TDR和PTE只提供业务交易窗口及隔离
数据目录，不传递策略内部数据集。策略计算接口输出目标仓位和诊断信息；资金、持仓与账户修订号
由执行宿主在生成执行计划时提供。策略实现发生变化时，冻结版本必须重新签署并完成全窗口决策
等价、订单成交等价和账户账本等价验证。

### 5. 联合搜索、边界审查与候选全集

参数搜索属于具体研究实验，可以在实验脚本中直接使用Optuna或其他合适的学习、搜索库，
无需为研究算法新增TDR入口。仓库不再维护通用Search或Feature Mining运行模块。每个study
应记录参数类型与边界、目标、约束、随机种子、算法和依赖版本；运行缓存只用于提效，正式
实验归档完整trial ledger及其身份。确需跨进程续跑时才使用独立SQLite；同名study的合同哈希
不同必须拒绝续跑。

搜索过程负责实例化`F`并寻找可行区域。它既影响收益和回撤，也必须证明结果位于稳定平台，不能
只报告最佳单点。对相互影响的权重、阈值、门控和退出参数默认执行内部联合搜索；冻结其他
参数的单维搜索只能回答条件诊断问题，不能据此否决完整原型。结构无效的组合记录为`PRUNED`，
计算失败不得假报成功。

初始边界应有金融或结构依据，不必一次无限放开。平台明显贴边时只对相关维度定向扩边，再次
联合搜索并判断依赖是否解除；无贴边证据时停止扩边。最终代表点从合格平台内部按预注册规则
选择，优先考虑平台中心、局部可行率和多指标中位水平，不选择回测最佳单点。

在排名前冻结完整候选台账。无论候选在哪一环节退出，都要记录输入无效、快速筛除、正式
筛除、进入排名、Pareto层级、临时冠军或体检失败，确保总数闭合。历史实验产物可以作为缓存，
但必须验证输入、实现版本和制品哈希。

### 6. 统一执行事实，TDR完成正式裁决

研究脚本可以自由探索数据、特征、原型和搜索方法，但正式候选的成交、费用、现金、持仓与
净值必须由TXE按EvaluationMandate独立复算。候选和正式版本统一使用：

- 因果可用的数据和明确定义的计算窗口、回测窗口；
- 策略批次冻结的成本、整手、价格精度、初始资金和仓位边界；
- 策略内嵌的唯一执行规则；
- 未成交、部分成交和累计成交的统一语义。

信号收益只用于解释；候选PK和冻结必须使用完整账户执行口径。

送审材料必须提供候选SRT、完整候选台账和`candidate_manifest.json`中的`review_data_sources`。
TDR的`application/review_data.py`校验研究池内相对路径、文件哈希与输入身份，把执行行情封存到
`data/review/<credential_id>/<submission_hash>/`；每个候选在快照内获得独立SRT数据目录，并由
`StrategyInstance.prepare_data()`准备策略依赖。正式复核只读取封存快照，输入缺失或损坏时
明确失败，不隐式联网补齐。评估产物写入独立审核目录，历史实验保持原样。

SE接收结构化事实，执行可计算、可复现的筛选和数值审计：

```text
完整候选台账 → 快速筛劣 → 多窗口非劣判断 → Pareto排名
             → 唯一临时冠军 → 完整体检 → 冻结评审资格
```

TDR组织的完整体检覆盖证据身份与完整性、正式PK、回放一致性、PBO/DSR/配对区块Bootstrap、
参数邻域、成本压力、外部复现、部署兼容和监测方案结构。SE只计算其结构化输入范围内的数值，
不读取仓库、理解金融语义、签发人工批准或改变SM/PTE状态。TDR验证候选、目标、数据、执行和
报告身份，强制检查体检矩阵是否完整，并生成与SGC绑定的AdjudicationReport。
`FAVORABLE/MIXED/WEAK/ADVERSE`是证据标签，用于披露不确定性，不等同于人工投资判断。

成本审计区分主口径、现实压力和极端诊断，只有送审时锁定的主口径与现实压力参与资格判断。
外部复现必须冻结公式并禁止按外部结果调参，同时披露交易数量、收益集中度和适用范围；一次
跨标的成功不能自动升级为普适机制。

首个候选没有在位策略时，以相同标的、资金、起止日和执行口径的BuyHold作为明确对手。
PK只授予体检资格，不能直接形成冻结版本。

### 7. 角色协同、冻结与前瞻观察

策略研究员负责创建研究批次、完成不可变实验，并在`research/SXXX/candidates/`手工组装包含
策略代码、binding、回测图代码和前瞻观察语义的完整候选提交包。投资总监负责使用平台工具
审查候选与最终EvaluationMandate、执行体检、阅读裁判报告、决定冻结并把冻结版本部署到SRT。
冻结、SRT部署和PTE账户启用是独立动作；平台当前沿用EvaluationMandate的`finalized_by`作为
操作者声明，但尚不做身份识别或鉴权，相关治理印章明确标记
`actor_identity_assurance=UNVERIFIED`。

正式冻结前重新核对封存数据、证据与运行时身份；重复评估也不能以缓存掩盖证据变化。
本轮架构升级保留历史研究档案供人工查看，不承诺旧研究脚本或旧数据制品兼容；已有五个冻结
版本均已迁入新的`StrategyImplementation`接口。需要改变源码闭包的版本在授权后重新签署，
并以冻结证据和完整等价测试证明决策及执行行为不变；新候选统一走候选SRT链路。

```powershell
# 策略研究员：创建研究批次
.\.venv\Scripts\czsc-trader.exe research create `
  --input research-intent.json --actor tomxiao --reason "批准研究立项"

# 同一策略族启动下一研究批次时，在输入JSON中保留相同name/scope，
# 并显式增加新的credential_id，例如SGC-S007-002。

# 投资总监：受理并锁定完整候选包和最终评价合同，再执行平台体检
.\.venv\Scripts\czsc-trader.exe candidate review `
  --package research/SXXX/candidates/SXXX-Cnnn `
  --mandate research/SXXX/mandates/SXXX-Cnnn.json
.\.venv\Scripts\czsc-trader.exe candidate evaluate SXXX-Cnnn

# 投资总监：阅读体检结果后决定正式冻结；该命令不会部署SRT或创建PTE账户
.\.venv\Scripts\czsc-trader.exe candidate freeze SXXX-Cnnn `
  --change-summary "首个冻结版本"

# 投资总监：将已冻结策略版本部署到SRT
.\.venv\Scripts\czsc-trader.exe strategy deploy SXXX-v1
.\.venv\Scripts\czsc-trader.exe strategy list SXXX
.\.venv\Scripts\czsc-trader.exe strategy info SXXX-v1
```

`research`命令的写入边界统一限定在研究区：

| 命令 | 功能 | 产物 |
| --- | --- | --- |
| `research create`（首批次） | 建立可修订的研究身份和首个预注册凭据 | `research/registrations/registry.json`、`research/registrations/SXXX/{family.json,lifecycle.jsonl,credentials/}`、`research/SXXX/HANDOFF.md` |
| `research create`（后续批次） | 在同一研究身份下建立新的研究批次 | 更新`research/registrations/SXXX/`并新增`research/SXXX/batches/*.md` |
| `research intent update` | 更新研究意图或研究状态 | 更新`research/registrations/SXXX/family.json`和`lifecycle.jsonl` |

上述产物都属于策略研究区，不进入`strategies/`。`candidate review`成功受理完整候选包时，
平台才把该批次必要的策略身份、凭据和原始提交内容导入策略治理区；体检失败会回滚本次导入。
`candidate freeze`把同一策略实现固化为治理区内的冻结发布包，`strategy deploy`写入经校验的
SRT部署凭据。策略实现始终保存在独立治理区，不复制到`packages/strategy_runtime/`。

冻结成功后，StrategyVersion进入`PAPER_READY`，但没有自动进入模拟盘。只有再次取得独立授权，
才在PTE创建虚拟账户。PTE记录部署后新增的信号、决策、订单、成交、账本和绩效。模拟盘用于
生成独立数据、验证执行和继续证伪，不能自动证明Alpha，也不能自动晋升实盘。监测触发人工
复核；暂停只阻止新单，不自动处理已有订单和持仓。PTE不读取未冻结候选包；它只消费已部署
冻结版本随决策输出的结构化观察事实，独立获取行情并异步生成统一前瞻观察图。

## S007最佳实践与经验教训

S007是当前工作流最完整的实践样本：它从第一性原理和全量输入普查开始，依次完成原型设计、
联合搜索、参数平台、代表点选择、统计审计、固定公式外部复现、正式账户回放、PK、体检、
人工冻结和PTE部署。它提供的是研究方法标杆，后续批次不能直接复制其七因子公式或参数。

### 应当复用的做法

1. **先建立输入全集，再讨论组合。** S007先审计数据的因果可用时间，再普查303条特征与期限
   路径，最后按职责、冗余和机制保留七个输入，避免只围绕熟悉的少数信号反复试参。
2. **把x、F和f分开治理。** FSC记录输入定义，STC记录门控评分原型，Optuna负责联合实例化；
   因子有效、原型合理和参数优秀是三个不同问题，证据不得混用。
3. **选择平台代表点，不追逐最佳单点。** S007从无边界依赖的主平台内，以多指标中位要求、
   局部可行率和中心距离选择代表配置，最终点距离平台中心0.0268且20近邻可行率100%。
4. **外部验证冻结公式。** 588300验证没有重新调参，并进一步披露单笔收益集中风险；外部结果
   只支持实际复现的范围，没有被包装成普适Alpha。
5. **不利证据和工程阻断原样保留。** 失败平台、错误审计口径、PBO/DSR混合证据及部署缺口
   都保留在后续实验中修正，没有回写历史结果或用工程修复抬高研究结论。
6. **让机器事实、数值审计和人工判断分层。** TXE生成标准成交与账户事实，SE执行可计算审计，
   TDR组织完整体检并生成裁判报告，SM只在人工确认后冻结，PTE只承担独立授权后的前瞻执行；
   外部专家意见作为研究输入，不替代内部裁决。

### 不可省略的研究过程

1. **目标口径校准。** S007从5bp过渡到10bp主成本，并将交易频率硬门从7笔调整为5笔。这是
   在研究目标和真实交易条件逐步明确后形成正式口径的必要过程；变更通过新实验生效，历史结果
   保持不变。后续批次应复用已经成熟的口径，但仍允许基于新标的职责建立自己的目标合同。
2. **原型消融与职责解耦。** 两个确认信息族同时进入基础分和确认门，只有经过配对消融和对等
   联合搜索，才能判断重复职责是否有价值。输入职责矩阵可以更早暴露疑点，但不能替代数值证伪。
3. **让策略实现成为研究锚点。** 在搜索前先用`StrategyImplementation`固化输入、因果范围和
   输出语义，搜索、历史回放和冻结复核调用同一路径。PTE部署仍在策略获得研究价值和冻结资格
   后独立建设，避免把交易渠道工作提前混入研究。
4. **对优秀结果继续证伪。** PBO、DSR、外部单笔集中和主标的大行情依赖必须与优秀回测同时
   披露。这些审计增加工作量，却是防止把幸运结果误判为稳定Alpha的必要成本。

### 真正影响效率的教训

1. **条件诊断一度被当成原型结论。** EX20/EX21只在旧锚点上调整确认门，无法判断九个相互
   作用参数的完整可行域。以后默认联合搜索；单维搜索必须预先标记为诊断，不授予淘汰资格。
2. **边界处理可以更早预注册。** S007在搜索后多次讨论贴边、扩边和再搜索。以后可在搜索合同
   中提前写明“贴边比例达到阈值时定向扩展一次”的规则，减少人工往返，同时保留完整trial账本。

后续批次默认沿用上述方法：节点一登记可修订的研究意图，输入普查后形成职责矩阵，原型通过
因果与实现冒烟检查后执行联合搜索，贴边时按预注册规则扩边，从稳定平台选择代表点；节点二
锁定最终目标和候选快照，再完成正式PK、完整体检和人工冻结。某一阶段没有合格证据时及时
停止，不通过降低标准制造候选。

## 数据与证据治理

### 开发池、内部验证与前瞻观察

- **开发池**：研究者已经查看、比较、调参或用于接受决策的数据；范围与具体`SXX`绑定。
- **内部验证**：开发池内的年度、滚动、留一和walk-forward窗口；用于检查稳定性，仍是开发证据。
- **前瞻观察**：策略版本完成选择后新产生、且未反向参与该版本选择的数据。

“测试集”不是数据的永久属性。查看前瞻图本身不会污染数据；一旦根据截止日后行情修改参数、
筛选候选或作接受决策，该区间就进入新候选的开发池，新版本必须登记新的选择截止日和前瞻
起点。旧版本的观察记录继续保留。

研究统一读取`data/raw/`受控研究池；普通回测读取`data/backtest/`。回测动作本身不判断污染，
污染治理由研究协议、批次截止和证据链完成。

### 发布结论前检查

1. 候选生成、阈值、窗口和人工选择是否看过所谓独立区间；
2. 同一结果是否经历多轮筛选，却只报告最后一次；
3. regime、因子、复权和执行价格是否只使用当时可得数据；
4. 前瞻表现是否被用于修改同一版本后仍拼接展示；
5. 高度相关候选是否被误当成少量独立试验；
6. 少量交易、高卡玛或单笔大赚是否被过度解释；
7. TDR事实、SE计算、人工判断和SM/PTE状态是否保持职责分离。

发生污染时，将相关区间归入开发池、更新新候选截止日并保留污染说明。禁止删除不利结果或
回写历史档案。

## 关键研究原则

- T日完整收盘信号只能驱动后续可执行时点，regime同样遵守滞后规则。
- 分钟K线和重复信号不等于独立样本；交易频率按独立闭合交易和交易日聚类衡量。
- 最大回撤、卡玛和盈亏比优先于单纯收益率，同时披露换手、成交率和收益代价。
- 参数平台优于孤立尖峰，但平台、PBO和DSR都不能替代前瞻观察。
- 搜索次数越多，幸运冠军风险越高；必须保留完整搜索账本和真实失败路径。
- 外部复现只能支持其实际检验的机制与范围，不能代替主标的归因。
- 信号、订单意图、渠道受理、部分成交和全部成交是不同事实，受理不等于成交。
- 没有具备实际意义的胜者时，保持原状态或终止批次，不为完成流程而创建候选。
