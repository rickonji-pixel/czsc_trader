# 策略研究交接

> 本文是策略研究领域的唯一总入口，用于跨机器、跨会话恢复研究工作。它维护研究批次索引、
> 当前标准工作流、数据与证据边界以及续作方法。具体策略的目标和当前结论读取
> `research/<策略ID>/HANDOFF.md`；不可变事实读取`experiments/`；正式身份与冻结版本读取
> `strategies/`。

安装、回测和PTE操作见[用户使用说明](../docs/USER_GUIDE.md)，架构、开发恢复和测试规则见
[技术交接](../docs/DEVELOPMENT_HANDOFF.md)。

## 研究批次与目标治理

每个`SXX`既是稳定策略ID，也是独立研究批次。研究目标不再由仓库级统一文件定义，必须绑定
具体`SXX`并写入对应`HANDOFF.md`，至少包含：

- 标的、资产类型、策略职责和需要证伪的金融假设；
- 开发池范围与截止日；
- 对手、收益目标、最大回撤、成本和仓位边界；
- 交易频率属于硬约束还是观察指标；
- 候选形成、PK、体检和停止研究的条件。

跨策略的用户偏好只能作为新批次立项目标的输入，不能自动成为全部策略的统一硬门。目标调整
从下一项预注册实验起生效；已经读取结果的区间属于开发证据，不能把事后调整包装成原始目标。
历史实验对旧`research/RESEARCH_MANDATE.md`的引用继续由Git历史和实验哈希解释，不回写实验
档案，也不影响当前工作流。

策略身份沿用以下层级：

```text
SXX 研究批次 → SXX-CXXX 研究候选 → SXX-vN 冻结版本 → 独立PTE虚拟账户
```

同一批次可以形成多个候选，但只能按冻结时的完整证据创建不可变版本。冻结版本进入模拟盘后
禁止原地调参；任何公式或参数变化都必须形成新候选并重新走完整流程。

## 标准研究工作流

### 1. 回到第一性原理

新批次先回答四个问题，再开始信号搜索：

1. 标的是什么资产，收益由哪些经济机制和催化因素驱动；
2. 哪些解释互相竞争，分别能提出什么可证伪假设；
3. 证伪需要哪些数据，何时可得，是否存在修订或时点穿越；
4. 用户希望策略承担什么职责，愿意接受怎样的收益、回撤、成本、仓位和证据速度。

结论写入`research/SXX/HANDOFF.md`，目标与开发截止在读取收益前冻结。机制故事只用于提出
假设，不能替代统计证据。

### 2. 创建不可变实验

实验目录采用`experiments/SXX/YYYYMMDD_SXX_EXnn/`，例如：

```text
01_goal.md                 研究问题和成功口径
02_design.md               数据、候选、窗口和评估协议
03_execution.md            实际运行、偏差和故障
04_conclusion.md           结论、限制和后续动作
run_experiment.py          本实验特有编排
artifacts/                 冻结输入、候选台账和机器证据
experiment_manifest.json   受管文件及哈希
```

实验ID全局唯一。完成并生成有效manifest后保持只读；发现错误时保留原实验，在新编号中修正
并声明继承关系。失败实验与不利结果同样保留。目录契约见
[实验档案说明](../experiments/README.md)。

单次实验只保存专属参数和编排。预计被两个以上实验复用，或进入正式运行链路的能力，进入
TDR或对应独立包，避免研究脚本复制生产逻辑。

### 3. 选择输入与策略模板

项目级FSC（Factor & Signal Catalog）位于`catalog/`，回答“项目已经有哪些信息族、因子和
信号定义”。研究批次通过`materials.json`绑定标的、数据和开发截止。FSC只复用定义；计算值、
缓存、收益和结论始终属于具体`SXX`。

因子与信号研究依次执行：

```text
FSC定义普查 → 标的内物化 → 技术质量过滤 → 去冗余
             → 职责互补选择 → 机制证伪 → 候选评价
```

技术过滤只处理数据质量、覆盖和状态密度，不能用收益提前筛定义。信息族选择必须解释金融
职责、时间尺度和重复信息，既避免只试单一信息族，也避免堆叠同族信号。

完成输入`x`后，从STC（Strategy Template Catalog）选择策略函数模板`F`。模板选择要记录
输入职责、参数边界、已知失效模式、目录摘要和确定性实例ID。同一轮只比较少量有机制依据的
模板；模板实例化只证明结构合法，不构成Alpha证据。

TDR的`feature_mining`可以用tsfresh提取小规模候选特征。所有结果标记为`DEVELOPMENT_ONLY`，
完成因果时序、去重和金融语义审查后才能登记FSC。

### 4. 参数搜索与候选全集

参数搜索统一通过`czsc_trader.search`调用Optuna。每个study必须冻结参数类型与边界、目标、
约束、随机种子和算法，默认使用InMemoryStorage并归档完整trial ledger。确需跨进程续跑时
才使用独立SQLite；同名study的合同哈希不同必须拒绝续跑。

Search负责实例化`F`并寻找可行区域。它既影响收益和回撤，也必须证明结果位于稳定平台，不能
只报告最佳单点。结构无效的组合记录为`PRUNED`，计算失败不得假报成功。

在排名前冻结完整候选台账。无论候选在哪一环节退出，都要记录输入无效、快速筛除、正式
筛除、进入排名、Pareto层级、临时冠军或体检失败，确保总数闭合。历史实验产物可以作为缓存，
但必须验证输入、实现版本和制品哈希。

### 5. TDR生成事实，SE执行评估

TDR统一负责数据加载、因子、regime、完整策略执行和确定性回测。研究候选和正式版本进入
同一回放核心，统一使用：

- 因果可用的数据和明确定义的计算窗口、回测窗口；
- 策略批次冻结的成本、整手、价格精度、初始资金和仓位边界；
- 策略内嵌的唯一执行规则；
- 未成交、部分成交和累计成交的统一语义。

信号收益只用于解释；候选PK和冻结必须使用完整账户执行口径。

SE接收TDR和实验提供的结构化事实，执行可计算、可复现的筛选与审计：

```text
完整候选台账 → 快速筛劣 → 多窗口非劣判断 → Pareto排名
             → 唯一临时冠军 → 完整体检 → 冻结评审资格
```

体检覆盖证据身份与完整性、正式PK、回放一致性、PBO/DSR/配对区块Bootstrap、参数邻域、
成本压力、外部复现、部署兼容和监测方案结构。SE不理解金融语义，不自行发明结论，也不改变
SM或PTE状态。`FAVORABLE/MIXED/WEAK/ADVERSE`是证据标签，用于披露不确定性，不等同于
人工投资判断。

首个候选没有在位策略时，以相同标的、资金、起止日和执行口径的BuyHold作为明确对手。
PK只授予体检资格，不能直接形成冻结版本。

### 6. 人工冻结与前瞻观察

唯一临时冠军通过完整体检且具备实际经济意义后，SE才签发与策略ID、候选ID、候选哈希和
来源哈希绑定的批准书。人工确认后由SM创建不可变版本，再在PTE建立独立10万元虚拟账户。

```powershell
.\.venv\Scripts\czsc-trader.exe strategy evaluate --experiment YYYYMMDD_SXXX_EXnn
.\.venv\Scripts\czsc-trader.exe strategy accept-evaluation `
  --experiment YYYYMMDD_SXXX_EXnn --actor tomxiao --reason "确认冻结并进入模拟盘"
```

PTE记录冻结后新增的信号、决策、订单、成交、账本和绩效。模拟盘用于生成独立数据、验证
执行和继续证伪，不能自动证明Alpha，也不能自动晋升实盘。监测触发人工复核；暂停只阻止
新单，不自动处理已有订单和持仓。

## 数据与证据治理

### 开发池、内部验证与前瞻观察

- **开发池**：研究者已经查看、比较、调参或用于接受决策的数据；范围与具体`SXX`绑定。
- **内部验证**：开发池内的年度、滚动、留一和walk-forward窗口；用于检查稳定性，仍是开发证据。
- **前瞻观察**：策略版本完成选择后新产生、且未反向参与该版本选择的数据。

“测试集”不是数据的永久属性。查看前瞻图本身不会污染数据；一旦根据截止日后行情修改参数、
筛选候选或作接受决策，该区间就进入新候选的开发池，新版本必须登记新的选择截止日和前瞻
起点。旧版本的观察记录继续保留。

研究统一读取`data/raw/`受控研究池；普通回测读取`data/backtest/`。回测动作本身不判断污染，
污染治理由研究协议、批次截止和证据链完成。

### 发布结论前检查

1. 候选生成、阈值、窗口和人工选择是否看过所谓独立区间；
2. 同一结果是否经历多轮筛选，却只报告最后一次；
3. regime、因子、复权和执行价格是否只使用当时可得数据；
4. 前瞻表现是否被用于修改同一版本后仍拼接展示；
5. 高度相关候选是否被误当成少量独立试验；
6. 少量交易、高卡玛或单笔大赚是否被过度解释；
7. TDR事实、SE计算、人工判断和SM/PTE状态是否保持职责分离。

发生污染时，将相关区间归入开发池、更新新候选截止日并保留污染说明。禁止删除不利结果或
回写历史档案。

## 关键研究原则

- T日完整收盘信号只能驱动后续可执行时点，regime同样遵守滞后规则。
- 分钟K线和重复信号不等于独立样本；交易频率按独立闭合交易和交易日聚类衡量。
- 最大回撤、卡玛和盈亏比优先于单纯收益率，同时披露换手、成交率和收益代价。
- 参数平台优于孤立尖峰，但平台、PBO和DSR都不能替代前瞻观察。
- 搜索次数越多，幸运冠军风险越高；必须保留完整搜索账本和真实失败路径。
- 外部复现只能支持其实际检验的机制与范围，不能代替主标的归因。
- 信号、订单意图、渠道受理、部分成交和全部成交是不同事实，受理不等于成交。
- 没有具备实际意义的胜者时，保持原状态或终止批次，不为完成流程而创建候选。

## 继续研究的最小步骤

1. 从上方索引进入对应`SXX/HANDOFF.md`；
2. 核对批次目标、标的、对手、开发截止、最近权威实验和禁止事项；
3. 验证研究数据、策略注册表和历史实验档案；
4. 创建下一个`YYYYMMDD_SXX_EXnn`并在读取结果前冻结协议；
5. 完成实验后只更新该批次当前结论、风险和下一步，不把交接写成历史流水账。

```powershell
git status --short --branch
$StrategyId = "S007"
$ResearchSymbol = "588080.SH"
.\.venv\Scripts\czsc-trader.exe data validate --symbol $ResearchSymbol
.\.venv\Scripts\czsc-trader.exe strategy show --strategy $StrategyId
.\.venv\Scripts\czsc-trader.exe strategy validate --all
.\.venv\Scripts\czsc-trader.exe archive validate --all
```

## 资料边界

| 路径 | 权威内容 |
| --- | --- |
| `research/SXX/HANDOFF.md` | 批次目标、当前结论、风险、下一步和禁止事项 |
| `research/SXX/materials.json` | 批次绑定的标的、数据和材料身份 |
| `experiments/SXX/` | 不可变实验、失败路径和机器证据 |
| `strategies/` | 正式策略身份、冻结版本、资格和治理证据 |
| `catalog/` | FSC信息族、因子和信号定义 |
| `strategy_templates/` | STC策略函数模板 |
| `data/raw/` | 受控研究数据 |
| `data/backtest/` | 可更新的普通回测数据 |
| `outputs/` | 可再生回测输出，不参与策略接受 |
| `state/paper_trading/` | 本机模拟盘运行记录，默认不随Git迁移 |

普通文本身份统一归一化LF，JSON规则使用语义SHA-256，行情CSV和二进制使用原始字节
SHA-256。新实现统一复用`src/czsc_trader/identity.py`，历史实验档案保持原样。
