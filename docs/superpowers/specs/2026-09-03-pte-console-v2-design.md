# PTE Console v2 设计

日期：2026-09-03  
开发分支：`codex/pte-console-v2`  
状态：用户已批准，已实现并完成本机8080验收

## 1. 背景

现有控制台由单渠道账户页面增量扩展而来。页面上半区读取Futu渠道账户，下半区读取
虚拟账户，浏览器选择虚拟账户时只更新局部区域。这使账户概览、策略决策、订单和账户
详情同时处于不同作用域，在多策略、多虚拟账户场景下存在误读和误操作风险。

Console v2以“任何资金、决策、订单和成交都必须属于唯一账户”为核心原则，重建页面
信息架构和API边界。虚拟账户是策略前瞻观察主体；Futu模拟账户是独立渠道验证主体；
PTE服务与数据发布属于全局系统层。

## 2. 目标与非目标

### 2.1 目标

- 账户、策略版本、决策、订单、成交和干预操作拥有唯一且可见的作用域。
- 多个虚拟账户可以独立观察、切换、暂停、恢复和审计。
- Futu账户、渠道决策、渠道订单和撤单集中到独立页面。
- Futu执行策略采用显式、持久化、可审计的绑定，不再隐式跟随最新策略版本。
- 页面刷新、深链接和轮询不会造成账户上下文丢失或旧响应覆盖新账户。
- 保持OPC团队可维护性：原生HTML/CSS/JavaScript，无前端构建链和大型框架。

### 2.2 非目标

- 不增加实盘交易能力。
- 不改变策略信号、执行定价和虚拟成交规则。
- 不允许多个策略同时向唯一Futu模拟账户提交订单。
- 不在比较页面执行暂停、恢复、绑定或撤单。
- 不在本轮增加通用用户、角色和权限系统。

## 3. 领域层级与不变量

控制台只有三个业务层级：

1. **系统层**：PTE进程、数据截止、调度、发布重试和全局告警。
2. **账户层**：虚拟账户或Futu渠道账户及其资金、持仓、决策、订单和成交。
3. **比较层**：多个虚拟账户在共同观察区间内的只读绩效比较。

必须保持以下不变量：

- 一个虚拟账户永久绑定一个`strategy_id + version + release_hash`。
- 一个决策、模型订单和模型成交只能属于一个虚拟账户。
- Futu渠道在任一时刻只绑定一个正式策略版本。
- Futu订单只属于Futu渠道账户，虚拟模型订单不提供Futu撤单操作。
- 所有干预请求在URL和请求体中携带明确资源身份，响应返回相同身份。
- 页面只渲染与当前URL账户一致的响应。
- 冻结新策略只创建虚拟账户，不自动改变Futu策略绑定。

## 4. 信息架构

页面顶部固定为系统状态栏，一级导航只有：

- `虚拟账户`
- `Futu渠道`
- `账户比较`

系统状态栏只展示PTE运行状态、数据截止、最近发布、下一次重试或任务时间、Futu连接
状态和全局告警数量。它不展示资金、持仓、策略决策和订单。

### 4.1 虚拟账户页

路由：`/accounts/{account_id}`。

页面采用左侧账户列表、右侧账户工作区的主从布局。左侧列表展示账户ID、策略发布身份、
运行状态、总资产、持仓、最新动作和账户告警。点击账户直接改变URL并加载完整账户快照。

右侧账户标题固定展示：

- 账户名称与账户ID
- 策略名称、`release_id`和发布哈希短码
- 策略资格
- 自动运行、暂停或阻塞状态
- 观察起点
- 仅作用于该账户的暂停/恢复开关

账户工作区按以下顺序展示：

1. 资金、持仓和累计收益概览。
2. 最新策略决策及未形成订单的原因。
3. 当前账户模型订单明细。
4. 当前账户模型成交明细。
5. 最大回撤、卡玛比率、盈亏比和完整审计信息。

切换账户时立即清空右侧旧数据并显示加载状态。加载失败时保留账户身份，所有业务值显示
不可用及错误原因，禁止继续展示上一个账户的数据。

### 4.2 Futu渠道页

路由：`/channels/futu`。

页面固定展示唯一Futu模拟账户：连接状态、行情状态、资金、实际持仓、当前绑定策略、
最新渠道决策、渠道订单、成交回报、失败退避和渠道事件。暂停/恢复渠道以及二次确认撤单
只在该页面出现。

页面必须同时展示绑定策略的`release_id`、发布哈希短码、绑定时间和绑定原因。渠道决策
返回的策略身份与持久化绑定不一致时，渠道进入阻塞状态并停止新单。

### 4.3 账户比较页

路由：`/comparison`。

比较页只展示虚拟账户在共同观察区间内的最大回撤、卡玛比率、盈亏比和累计收益，并允许
选择参与比较的账户。它不展示订单，不提供任何交易干预操作。

## 5. Futu策略显式绑定

PTE运行库使用`settings`表保存`futu_strategy_binding` JSON：

```json
{
  "strategy_id": "S001",
  "strategy_version": "v2",
  "release_id": "S001-v2",
  "release_hash": "146490...",
  "bound_at": "2026-09-03T22:00:00+08:00",
  "bound_by": "tomxiao",
  "reason": "人工确认切换Futu模拟执行策略"
}
```

绑定通过CLI执行：

```powershell
.\.venv\Scripts\pte.exe channel bind-strategy `
  --repo-root . `
  --channel futu --strategy S001 --strategy-version v2 `
  --actor tomxiao --reason "人工确认切换Futu模拟执行策略"
```

PTE通过Trader CLI校验策略资格、版本和发布哈希后写入绑定及审计事件。存在活动渠道订单时
拒绝切换。重复绑定相同发布身份保持幂等。页面首版只读展示绑定，避免把策略治理操作变成
容易误触的按钮。

现有运行库迁移时优先采用最近一次渠道决策中已经实际使用的策略身份建立初始绑定；没有
历史决策时保持未绑定，Futu渠道继续对账但不生成新决策和新订单。

## 6. HTTP契约

Console v2使用资源级接口：

```text
GET  /api/system/status
GET  /api/virtual-accounts
GET  /api/virtual-accounts/{account_id}/snapshot
POST /api/virtual-accounts/{account_id}/pause
POST /api/virtual-accounts/{account_id}/resume
GET  /api/channels/futu/snapshot
POST /api/channels/futu/pause
POST /api/channels/futu/resume
POST /api/channels/futu/cancel-token
POST /api/channels/futu/cancel
GET  /api/comparison?account_id=...
```

虚拟账户快照统一返回：

```json
{
  "scope": {
    "account_id": "s001-v2",
    "strategy_id": "S001",
    "release_id": "S001-v2",
    "release_hash": "..."
  },
  "as_of": "2026-09-03T22:00:00+08:00",
  "account": {},
  "decision": {},
  "orders": [],
  "fills": [],
  "metrics": {},
  "alerts": []
}
```

`/api/status`在兼容期继续保留，供watchdog健康检查和旧客户端使用；Console v2不消费该
聚合响应。服务端不再返回具有误导性的`selected_account`，默认入口只返回
`default_account_id`。

## 7. 浏览器状态与轮询

- 当前账户以URL为唯一事实来源，`localStorage`只记录下次进入时的导航偏好。
- 系统状态每10秒刷新，当前账户或Futu渠道快照每5秒刷新。
- 每次账户切换递增请求序号并取消旧请求；迟到响应必须丢弃。
- 每个响应在渲染前校验`account_id`和发布身份。
- 页面断线后保留当前路由和身份标题，业务数据进入过期状态并显示最后成功时间。
- 恢复连接后重新获取完整快照，不用增量响应推测状态。

## 8. 告警归属

- 数据发布、调度和进程问题归入系统告警。
- 虚拟决策、模型订单和模型结算问题归入对应虚拟账户告警。
- Futu连接、行情、账户、委托和成交问题归入Futu渠道告警。

所有账户级事件写入`account_id`；所有渠道级事件写入`channel=futu`。页面不通过错误文本
猜测归属。

## 9. 代码组织

保持PTE独立包和无构建链约束，将当前单文件内嵌页面拆分为：

```text
packages/paper_trading_engine/src/paper_trading_engine/
  web.py
  web_api.py
  channel_binding.py
  static/
    index.html
    app.js
    styles.css
```

- `web.py`只负责HTTP路由、内容类型和异常映射。
- `web_api.py`负责构建系统、账户、渠道和比较快照。
- `channel_binding.py`负责绑定模型、校验、迁移和审计。
- `app.js`负责路由、请求生命周期和渲染，不包含交易规则。
- `styles.css`负责桌面及移动布局。

静态资源作为Python包数据发布。继续使用标准库HTTP服务，不增加Node运行时和前端框架。

## 10. 操作安全

- 虚拟账户暂停立即生效且可恢复，只阻止该账户新模型订单。
- Futu渠道暂停只阻止新渠道订单，已有渠道订单继续对账。
- Futu撤单保留两分钟令牌和二次确认，确认框显示渠道、订单号、方向、数量和策略版本。
- 策略绑定只能通过带`actor/reason`的CLI执行，并记录旧绑定和新绑定。
- 任一身份校验失败都停止新单，账户和渠道对账继续运行。

## 11. 测试与验收

### 11.1 自动测试

- API测试证明每个账户快照只包含该账户的决策、订单、成交和告警。
- 路由测试证明深链接、刷新和未知账户行为正确。
- JavaScript状态测试证明迟到响应不能覆盖新账户。
- 页面测试证明账户切换同时更新账户、决策、订单、成交和开关。
- 渠道测试证明虚拟订单不出现撤单按钮，Futu订单只在渠道页撤单。
- 绑定测试覆盖迁移、幂等、活动订单阻塞、身份不一致阻塞和审计记录。
- 保留全部现有PTE账本、调度、watchdog和Trader契约测试。

### 11.2 人工验收

在8080真实运行库中至少完成：

1. 在`baseline-143`与`s001-v2`之间往返切换。
2. 核对标题、资金、持仓、决策、订单、成交和开关始终属于同一账户。
3. 刷新`/accounts/s001-v2`后仍停留在该账户。
4. 验证Futu渠道页独立显示渠道账户、绑定策略和渠道订单。
5. 验证虚拟账户页面没有Futu撤单入口。
6. 验证窄屏下账户列表和工作区不发生横向覆盖。

## 12. 迁移与交付

开发不改写现有SQLite交易记录。新增设置和审计字段采用幂等迁移。上线时重启
`CZSC-PTE-Watchdog`加载新代码，重启后验证系统状态、两个虚拟账户、Futu绑定和最近
决策身份。交付同时更新PTE README与开发交接文档。

旧的单页聚合控制台在Console v2验收通过后移除，不保留两套可编辑界面。
