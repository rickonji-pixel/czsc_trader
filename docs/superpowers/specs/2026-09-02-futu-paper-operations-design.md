# Futu 模拟交易观测与干预设计

## 目标

为 `SH.588080` 提供一个本机持续运行的模拟交易页面。系统自动读取活动冻结
基线与执行规则、对账 Futu 中国市场模拟账户、提交必要的新订单，并允许用户
暂停新单、恢复运行和二次确认撤单。观察从 2026-09-01 收盘信号、2026-09-02
首次执行开始，不再拆分其他起点口径。

## 范围

首版只实现 P0：运行身份、健康状态、最新决策、账户对账、订单生命周期、
自动提交、撤单确认、暂停/恢复、重启恢复、告警和审计。样本外收益比较属于
后续 P1。系统只允许 `TrdEnv.SIMULATE`、`TrdMarket.CN`、`SH.588080`、
`TimeInForce.DAY` 和 100 份整数倍。

## 结构

- `paper_trading.py`：运行状态、SQLite 事件存储、券商协议、安全约束和单次协调。
- `futu_gateway.py`：Futu SDK 适配；账户号与订单号不写入页面日志明文。
- `paper_web.py`：本机 HTTP 页面、JSON 状态和暂停/恢复/撤单接口。
- CLI `paper serve`：启动协调循环和页面。

运行态数据库固定写入 `state/futu_paper/runtime.db`，由仓库 `.gitignore` 排除。
每次启动先从 Futu 查询账户、持仓和订单，完成恢复后才允许新订单。订单状态
和累计成交数量是成交依据；委托受理不更新仓位。缺少实时行情显示
`DEGRADED_QUOTE`，但不阻止自动提交。正式信号只使用最新完整收盘数据。

## 自动执行

协调循环先读取 Futu 实际持仓，再调用现有 `run_advice`。目标与实际一致时只
保存快照。出现买入指令时，使用冻结执行规则给出的买入限价自动提交。首版
若出现无法生成数值价格的卖出指令，进入 `ACTION_REQUIRED` 并暂停新单，避免
未经冻结的市价替代规则。每个信号日期、方向和冻结身份组成幂等键；本地或
Futu 已存在对应订单时不重复提交。

## 干预与审计

暂停只阻止新订单，继续轮询和对账已有订单。恢复前要求最近一次对账成功。
撤单请求必须携带页面生成的确认令牌，令牌单次使用并绑定订单。暂停、恢复、
撤单、连接异常、订单提交和订单状态变化全部追加到 SQLite 审计表。

## 页面

单页显示环境硬锁、活动基线、数据截止、策略目标、账户仓位、现金、总资产、
冻结资金、活动订单、最近事件与告警。页面每五秒刷新。服务只监听
`127.0.0.1`，不提供远程访问和用户系统。

## 验证

单元测试使用内存券商验证安全硬锁、幂等、成交增量、暂停语义和撤单确认；
HTTP 测试验证状态与干预接口。真实 Futu 只执行只读启动验证；既有 100 份
提交—撤单探针已经证明写链路可用，不在自动化测试中重复下单。
