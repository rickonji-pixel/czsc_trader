# SE 临时冠军完整审计设计

## 1. 背景与目标

OPC-v2 已能对完整候选池完成筛劣、非劣检验、Pareto 分层和临时冠军选择，但冻结前体检
仍分散在 Trader，且统计稳健性证据不完整。该结构让 SE 只拥有部分裁决能力，也容易把
“审计执行完成”误读为“统计显著性已经通过”。

本次交付新增 `opc-v3`，将临时冠军的原有工程审计和新增统计审计全部内聚到 Strategy
Evaluator（SE）。Trader 只生产事实数据、按 SE 声明的压力场景运行回测、管理缓存和实验
文件，并调用 SE。首版统计结果由人工裁决，不设置统计数值自动否决线。

## 2. 边界与依赖

依赖方向保持为：

```text
CZSC Trader -> Strategy Evaluator
```

SE 负责：

- 执行因果一致性审计；
- 精确重算一致性审计；
- 候选试验账本、配置身份和行为身份审计；
- 双倍费率及 15/30/50bp 不利滑点结果的完整性和相对表现审计；
- CSCV/PBO、DSR、配对平稳区块 Bootstrap；
- 真实参数邻域和平原检验；
- 证据完整性、哈希、随机协议和可复现性校验；
- 风险标签、`opc-v3` 最终决策和审计报告内容。

Trader 负责：

- 生成候选逐日净收益、交易记录、参数向量、正式指标和试验台账；
- 按 SE 返回的场景规范运行正式执行规则、费率和滑点压力回放；
- 把 Pandas/回测对象转换为 SE 的不可变输入记录；
- 持久化并校验缓存文件、原子写入实验产物；
- 展示 SE 返回的报告并承接人工冻结确认。

SE 不读取仓库路径、不直接运行 Trader 回测、不修改 SM/PTE 状态。SE 允许依赖 NumPy 和
SciPy；跨包公开契约仍使用冻结 dataclass、标量和 tuple，不暴露 Pandas 对象。

## 3. OPC-v3 决策语义

`opc-v1`、`opc-v2`和历史实验保持不可变。`opc-v3`沿用 `opc-v2` 的确定性筛选和排名规则，
并要求临时冠军完整审计证据。

- 没有合格临时冠军：沿用现有 `KEEP_INCUMBENT` 或并列时的
  `INSUFFICIENT_EVIDENCE`；
- 原有工程审计任一项 `FAIL`：`KEEP_INCUMBENT`；
- 任一必需审计缺失、身份不匹配、样本不足或计算失败：
  `INSUFFICIENT_EVIDENCE`；
- 确定性规则通过、工程审计通过、统计审计完整：`RECOMMEND_FREEZE`；
- 统计结果只产生 `FAVORABLE`、`MIXED`、`WEAK` 风险标签，不在首版自动改变
  `RECOMMEND_FREEZE`。

因此 `RECOMMEND_FREEZE + WEAK` 是合法结果，报告必须醒目标注统计风险，最终由操作者接受
或拒绝。统计审计完成只代表证据完整，不代表优势已获统计证明。

## 4. 统一输入与身份

SE 提供一个公开用例入口：

```python
audit_provisional_champion(request: ChampionAuditRequest) -> ChampionAuditResult
```

`ChampionAuditRequest`包含：

- `AuditIdentity`：实验 ID、候选池 hash、数据截止日、数据 hash、执行规则 hash、
  OPC 标准版本、审计协议版本和随机种子；
- 临时冠军、在位策略和 Pareto 第一层其他候选 ID；
- 行为去重后的完整挑战者日收益矩阵，所有列共享同一交易日索引；
- 临时冠军、在位策略和第一层比较者的日收益；
- 全候选参数向量、行为 hash、资格、Pareto 层和四指标最差画像；
- 标准执行的目标仓位、因子分数、事件与订单事实；
- 正式重算结果和原始正式结果；
- 完整试验台账；
- Trader 按 SE 场景规范生成的压力结果。

所有数组必须有限、长度一致、日期唯一递增。候选池、收益矩阵、参数表、执行事实、重算
结果和压力结果分别计算规范 hash，并与 `AuditIdentity`绑定。SE 对内容重新计算 hash；缓存
命中不能绕过身份校验。

## 5. 原有工程审计

### 5.1 执行因果一致性

SE 验证目标仓位位于 `[0, 1]`、日期唯一递增、分数索引一致；每笔订单必须在信号后的下一
交易日执行，并唯一对应 `Entry`、`Increase`、`Reduce` 或 `Exit`事件；事件前后仓位及因子
分数必须与目标序列一致。任何不一致均为 `FAIL`。

### 5.2 精确重算

SE 对正式结果和独立重算结果执行规范序列化比较。候选、窗口、场景、指标值、指标状态和
交易数量必须完全一致；浮点值使用 `1e-12`绝对容差。缺少任一正式窗口为
`INSUFFICIENT`，数值或状态不一致为 `FAIL`。

### 5.3 试验账本和身份

每个候选必须存在至少一条试验记录；试验策略 hash 必须匹配候选配置；行为去重代表必须可
追溯；临时冠军必须属于正式排名集合。缺项为 `INSUFFICIENT`，矛盾为 `FAIL`。

### 5.4 执行压力

SE 固定声明场景：`fee_x2`、`slippage_15bp`、`slippage_30bp`、`slippage_50bp`。滑点施加
在实际次日成交价：买入价上调、卖出价下调。Trader 负责回放，SE 校验场景齐全、执行规则
身份一致，并计算临时冠军相对在位策略的四指标变化、绝对退化和优势收缩率。结果仅作工程
风险披露；场景缺失为 `INSUFFICIENT`，执行身份矛盾为 `FAIL`。

## 6. 统计审计

### 6.1 CSCV/PBO

输入为行为去重后的完整挑战者逐日收益矩阵，不把未参与搜索的在位策略计入搜索候选。固定
划分为 10 个连续近等长区块，枚举 `C(10, 5)=252`个互补训练/验证切分。每个训练半区按
零无风险利率年化 Sharpe 选择候选，记录验证半区排名百分位和 logit。

输出 PBO、验证百分位中位数、logit 中位数、每个候选被选频次及验证排名分布。该结果明确
标注为“标准 Sharpe-PBO 诊断”，不声称精确复刻 OPC 多目标选择器。

### 6.2 DSR

使用完整挑战者候选 Sharpe 分布计算临时冠军的 Deflated Sharpe Ratio。报告：

- 原始实际尝试数量；
- 行为去重数量；
- 候选收益相关矩阵特征值参与率得到的有效维度；
- 按原始试验数和有效试验数分别计算的期望最大 Sharpe 与 DSR 概率。

S001 等在位策略不作为 DSR 的零假设基准；临时冠军与在位策略的差异由配对 Bootstrap
单独回答。

### 6.3 配对平稳区块 Bootstrap

比较临时冠军与在位策略，并比较临时冠军与 Pareto 第一层其他候选。双方必须使用同一日期
的配对日收益。固定 `10,000`次重复，平均区块长度 21 个交易日为主结果，10 和 42 个交易
日为敏感性结果；随机种子来自 `AuditIdentity`。

每次重采样计算 CAGR、最大回撤和卡玛差异。最大回撤使用“候选最大回撤减比较者最大回撤”
作为有利方向，数值越大表示回撤越浅。输出差异点估计、95%区间、有利概率及三个区块长度
的方向一致性。不对低频 Profit Factor 构造逐日 Bootstrap 伪置信区间。

### 6.4 参数邻域和平原

使用完整候选池已有参数，不额外生成 200 个扰动候选。按预注册的 Range 权重坐标计算 L1
距离，行为 hash 去重后选择最近 20 个邻居。输出距离、正式资格、Pareto 层、四指标最差
画像，以及邻域画像的中位数、Q1、最差值和相对冠军退化。

有效邻居少于 10 个时，本项为 `INSUFFICIENT`。邻域统计只产生风险标签，不设置参数平原
自动否决线。原有同 family/parameter_group 的布尔邻域检查由本项替代。

## 7. 风险标签

每项统计审计先输出结构化事实和方向标记，再汇总为：

- `FAVORABLE`：所有必需结果完整，主要结果和敏感性结果多数支持临时冠军；
- `MIXED`：结果完整，但方向存在明显分歧；
- `WEAK`：结果完整，多数主要结果不支持临时冠军。

标签规则属于 SE 的版本化标准，报告同时展示原始概率、区间和邻域统计，避免标签替代人工
判断。首版标签不构成冻结门槛。

## 8. 产物与报告

Trader 持久化 SE 返回的一个主摘要和必要明细：

```text
statistical_audit.json
cscv_splits.csv
bootstrap_comparisons.csv
parameter_neighborhood.csv
execution_stress.csv
evaluation_report.md
evaluation_result.json
```

候选逐日收益矩阵作为可复用实验产物单独保存，其内容 hash 进入
`statistical_audit.json`。`evaluation_result.json`的决策 hash覆盖统计摘要和上述审计产物
hash。幂等打开已完成实验时必须重新验证。

一页主报告固定展示：最终建议与证据边界、确定性比较、PBO/DSR、配对 Bootstrap、参数
邻域、执行压力、风险标签和人工裁决提示。统计风险最多提炼三条，完整明细留在 JSON/CSV。

## 9. 失败、性能与确定性

- 任一必需统计输入缺失、非有限、日期错位或身份不一致，返回
  `INSUFFICIENT_EVIDENCE`，禁止用旧结果或默认值填补；
- 计算中断时保留已完成的缓存事实，但不生成完整审计结论；
- 相同输入、版本和随机种子必须生成相同摘要和明细；
- 缓存键至少覆盖候选池、截止日、数据、执行规则、审计协议和种子；
- 当前约 1,187 个候选规模下，OPC-v3 完整冷启动目标不超过 5 分钟；
- 已有候选收益矩阵时，单独统计审计目标不超过 2 分钟；
- 优先使用矩阵化和预计算区块统计量，并行只作为补充。

## 10. 测试与迁移

SE 单元测试覆盖合成收益下的 PBO、DSR、有效维度、固定种子平稳区块 Bootstrap、真实邻域、
执行因果、重算、账本、压力场景、风险标签和三种决策。契约测试覆盖日期错位、非有限值、
错误 hash、缺少场景和邻居不足。

Trader 集成测试覆盖 DataFrame 到不可变契约适配、收益矩阵缓存、压力场景回放、原子产物、
报告渲染、幂等 hash 验证和 `accept-evaluation` 对完整审计的强制要求。

迁移完成后新建 EX06，复用 EX05 的冻结候选池和开发截止日，以 `opc-v3`重新评估 R1102、
R0539及全部候选。EX05 保持原样。EX06 完成人工裁决前暂停进一步 Range 参数搜索，不创建
影子账户，不自动注册 PTE，不自动冻结策略。
