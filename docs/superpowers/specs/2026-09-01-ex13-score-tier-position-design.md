# EX13计分分档仓位研究设计

日期：2026-09-01  
标的：588080.SH  
研究基准：0901_EX13历史挑战者

## 1. 研究目标

检验EX13的连续决策计分是否包含可用于仓位管理的强弱信息；只有计分与未来收益、路径回撤之间存在跨年稳定的单调关系时，才允许搜索简单分档仓位。最终挑战者必须在2021—2025连续窗口保持EX13净收益率不下降，并严格改善最大回撤。

本计划不重新选择因子，不修改EX13的13个因子、权重、归一化定义、计分公式、入场阈值、退出阈值或事件定义。2026不参与诊断、分档设计、参数选择或失败后的规则修改。

## 2. 已知事实与需要纠正的解释

EX13计分不是“冠军计分加一个偶发事件”这么简单。其公式为：

```text
EX13_score = 0.8 × baseline_20260826_score + 0.2 × risk_relief_event
```

当事件为0时，EX13计分仍会在每个交易日变为冠军计分的80%。2026截至8月28日事件为0，但159个交易日的计分全部不同；其中7日改变了是否高于入场阈值的分类，只因当时已经持仓，最终目标仓位才没有变化。因此EX15“事件未出现所以策略相同”的表述必须修正为“计分不同，但状态机吸收了差异，目标仓位相同”。

这个事实同时构成本轮假设：连续计分可能包含未被二元状态机利用的置信度信息，但必须先证明计分强弱与未来路径存在稳定关系。

## 3. 实验结构与停止条件

计划最多包含三个实验：

1. **计分单调性诊断**：只分析，不构造策略；
2. **分档仓位挑战**：仅在诊断PASS后执行；
3. **终局汇总**：冻结胜者或终止该路线。

若诊断FAIL，直接停止，不启动仓位搜索。若诊断PASS但所有仓位候选FAIL，终止分档仓位路线，不允许事后增加档位、搜索阈值或调整因子权重。

## 4. 计分单调性诊断

### 4.1 数据与状态

- 2020只用于CZSC和状态机初始化；评价期固定为2021-01-01至2025-12-31。
- 每个交易日T只使用T日收盘前完整数据计算EX13计分。
- 分别分析全部交易日和EX13目标仓位为1的交易日；仓位管理的正式判定以持仓状态样本为主。
- 未来端点固定为5、10、20个交易日收益率和路径最大回撤，20日为主端点。

### 4.2 固定分档

使用EX13已有退出和入场阈值定义五档，不利用未来结果寻找分界：

| 档位 | 分数范围 | 语义 |
|---|---|---|
| S0 | `score <= 0.025` | 退出区 |
| S1 | `0.025 < score < 0.075` | 弱保持区 |
| S2 | `0.075 <= score < 0.125` | 中性区 |
| S3 | `0.125 <= score < 0.175` | 强保持区 |
| S4 | `score >= 0.175` | 入场/高置信区 |

每档必须报告总样本数、逐年样本数、未来收益、路径最大回撤、胜率和bootstrap区间。少于30个持仓日的年度档位记为支持度不足，不通过缺失年度规避稳定性判断。

### 4.3 诊断PASS门槛

持仓状态样本必须同时满足：

1. S4相对S1/S2合并组的20日平均收益不低，且20日平均最大回撤更小；
2. 上述两个差异至少4/5年度方向一致；
3. 将档位序号视为有序变量、控制EX13二元目标仓位和风险缓解事件后，20日路径最大回撤的Newey–West HAC系数方向为正，双侧`p <= 0.10`；
4. 诊断结果不由单一年度贡献超过绝对效应总和的50%；
5. 因果前缀重放逐值一致。

收益端点只要求不呈稳定反向；正式策略仍由回测硬门槛约束收益。若任一门槛失败，诊断状态为FAIL。

## 5. 分档仓位策略

### 5.1 统一状态机

分档仓位不是冻结二元路径之外的覆盖层，而是EX13计分状态机直接输出`0/0.5/0.75/1`目标仓位：

- 空仓时仍只有`score >= 0.175`才允许入场，首次仓位为1；
- 持仓达到EX13固定最短持仓3日后，按分数档位调整仓位；
- `score <= 0.025`沿用EX13退出逻辑并清仓；
- 档位变化在下一交易日开盘执行；
- 不使用日期、盈亏、Buy & Hold表现或未来路径触发仓位。

### 5.2 有限候选空间

只允许以下4个固定映射：

| 候选 | S1 | S2 | S3 | S4 |
|---|---:|---:|---:|---:|
| M1 | 0.5 | 0.75 | 1.0 | 1.0 |
| M2 | 0.5 | 0.5 | 0.75 | 1.0 |
| M3 | 0.5 | 0.75 | 0.75 | 1.0 |
| M4 | 0.5 | 0.5 | 1.0 | 1.0 |

S0始终为0。分界固定为诊断中的`0.075`、`0.125`和EX13原阈值`0.025/0.175`，不作为搜索参数。不得加入0.25仓位、连续函数、额外确认参数或新的风险指标。为抑制边界抖动，非清仓档位变化必须连续两日确认；退出仍沿用EX13原规则。

### 5.3 选择与PASS

比较基准固定为EX13，而不是`baseline_20260826`。所有候选使用相同的2021—2025连续资金窗口、单边费用0.0005和初始资金1,000,000。

候选只有同时满足以下条件才PASS：

1. 净收益率不低于EX13，数值容差`1e-12`；
2. 最大回撤严格优于EX13，数值容差`1e-12`；
3. 因果、订单、资金账本和档位状态转换审计全部PASS。

若多个候选PASS，依次按最大回撤、净收益率、夏普率、较少换仓次数和较简单映射排序。逐年收益、逐年回撤、持仓率、费用0/0.0005/0.001敏感性全部报告，但不另设事后门槛。

## 6. 2026与冠军资格

仓位挑战者必须在2021—2025选择完成并冻结后，才能执行一次2026Q1、H1和1—8月回看。2026结果不得反向修改策略。

由于2026截至8月28日已经被观察，这次回看只描述冻结策略在已见历史中的行为，不构成独立样本外证据。即便三窗口胜出，也只形成新的历史挑战者；是否替换活动基线仍需单独决策。真正前向证据从2026-08-28之后积累。

## 7. 实现边界

新增组件应保持职责分离：

- 纯函数模块负责分数分档、两日确认和目标仓位生成；
- 诊断runner只生成支持度、逐年效应、HAC和因果证据；
- 策略runner只读取冻结诊断结论和候选映射，运行回测与审计；
- 研究handler只连接标准`czsc-trader experiment run`入口；
- 所有正式证据进入新的`experiments/MMDD_EXX/`档案，运行态缓存和普通回测不得替代研究档案。

错误处理必须拒绝诊断或选择阶段晚于2025-12-31的截止日、父档案哈希不符、EX13身份不符、档位越界、非单调仓位、缺失前置信号和未声明候选。冻结后回看runner只允许协议声明的2026-08-28截止日。

## 8. 测试与交付

至少覆盖：

1. 分数边界归档正确；
2. 两日确认不会使用未来值；
3. 退出优先于非零仓位分档；
4. 目标仓位只属于`0/0.5/0.75/1`；
5. T日决定只在T+1开盘执行；
6. 收益不下降与回撤严格改善门槛；
7. 父档案和2026访问边界；
8. 全部实验档案哈希验证。

交付包括诊断档案、候选映射与逐项指标、订单和仓位路径、费用敏感性、冻结挑战者或终止报告，以及更新后的跨机交接文档。活动基线注册表默认不修改。
