# PTE虚拟账户前瞻观察图设计

日期：2026-09-04  
状态：待评审  
目标分支：`codex/pte-account-chart`

## 1. 背景与目标

PTE虚拟账户页已经能够展示策略发布、最新决策、订单、成交和绩效，但缺少把这些事实放回
行情环境中观察的入口。用户希望参考
`outputs/588080_0903_BT03/chart_2026FULL.html`的视觉和交互方式，查看每个冻结策略在选择
截止日之后实际产生的信号。

本功能提供账户级只读前瞻观察图，回答四个问题：

1. 该账户绑定的策略版本见过哪些开发数据；
2. 选择截止日之后出现了哪些新行情；
3. PTE实际生成了哪些信号和目标仓位；
4. 信号随后形成了哪些订单意图、渠道订单和明确成交。

图表用于观察与审计，不参与策略计算、交易决策或自动晋升。

## 2. 范围

### 2.1 本期包含

- 虚拟账户页新增“前瞻观察”图表，位于“最新决策”之后、“订单”之前；
- 默认显示选择截止日前180个交易日，以及截止日后的全部可用日线；
- 上图展示日K、CZSC笔、BUY/SELL信号和交易标记；
- 下图展示目标持仓与实际持仓；
- 明确标出策略选择截止线，并区分“开发背景”和“前瞻观察”区域；
- 图表身份绑定账户ID、策略发布ID、发布哈希和选择截止日；
- 使用本地Plotly资源，控制台不依赖CDN；
- 内容未变化时复用缓存，账户页轮询不触发重复渲染。

### 2.2 本期不包含

- 截止日前历史信号重算；
- 因子曲线、评分拆解或候选比较；
- 图上修改参数、生成决策、下单或撤单；
- Futu行情调用；
- 多标的叠加、分钟图和账户间同图比较；
- 将图表浏览行为自动登记为研究证据。

## 3. 设计原则

1. **账户归属明确**：每张图只对应一个虚拟账户和一个不可变策略发布。
2. **前瞻事实优先**：信号来自PTE已持久化决策，订单和成交来自账户账本。
3. **不补造历史**：选择截止日前只显示行情背景和CZSC笔，不补算该账户从未生成的信号。
4. **包边界稳定**：PTE通过stdin/stdout调用TDR纯绘图器，不导入`czsc_trader`，也不向
   TDR移交前瞻行情的存储权。
5. **交易链路隔离**：绘图失败只影响图表，不能阻塞调度、决策、下单、回报或对账。
6. **本地可用**：全部脚本和图表资源由本机服务提供，不访问公网。
7. **OPC可维护**：复用现有绘图能力、现有完整功能测试和简单文件缓存。

## 4. 页面与交互

### 4.1 布局

虚拟账户页顺序调整为：

```text
账户身份与运行开关
核心账户指标
最新决策
前瞻观察图
订单
成交
绩效与审计
```

图表卡片标题为“前瞻观察”，右侧显示`S001-vN · 选择截止 YYYY-MM-DD`。卡片顶部固定
提示：“截止线左侧仅作行情背景；右侧为该策略版本的前瞻观察记录。”

### 4.2 图形

整体参考现有TDR回测图：白色绘图区、上下共享日期轴、横向图例、统一日期悬停、隐藏非
交易日、响应式宽度。图高约760像素，上下比例为72%/28%。

上图元素：

- 日K：红涨绿跌；透明辅助点承接统一悬停，沿用已修复的K线可瞄准方案；
- CZSC笔：蓝色折线和端点；
- BUY信号：红色向上三角，定位在信号日K线下方；
- SELL信号：绿色向下三角，定位在信号日K线上方；
- 订单意图：空心圆，定位在有效交易日，悬停显示意图ID、数量和限价；
- 明确成交：星形，按实际成交日期与价格定位，悬停显示Futu订单、数量、费用和关联决策；
- 选择截止：红色竖向虚线；
- 前瞻区域：截止线右侧使用低透明度蓝色背景。

下图元素：

- 目标持仓：阶梯线，来自PTE决策的`target_quantity`；
- 实际持仓：阶梯线，来自账户日快照；
- 缺少日快照时保持空缺，不使用目标仓位推断实际成交持仓。

WAIT决策不绘制价格标记，其目标仓位仍进入下图。部分成交按每条成交增量分别展示。

### 4.3 状态

- 加载中：卡片内骨架占位，不刷新整个页面；
- 无前瞻信号：正常显示K线、截止线和“当前尚无买卖信号”；
- 无截止日后行情：显示180日背景并提示“等待新的完整收盘数据”；
- 图表不可用：显示错误摘要和“重新加载图表”，账户其他区域继续工作；
- 切换账户：取消旧请求，并在接收结果时再次校验账户ID，防止串图；
- 内容未变化：保留现有Plotly实例、缩放范围和悬停状态。

## 5. 数据语义

### 5.1 行情

PTE拥有运行数据目录中的`{code}_daily_*.csv`和对应manifest。PTE验证发布身份后读取
日线，在内存中截取选择截止日前最后180个交易日和截止日后的全部交易日，再把有限窗口
内的OHLC数据写入绘图请求。TDR不读取PTE运行目录、`data/raw`或其他行情文件。

图中的策略信号定位在后复权行情上。订单意图和成交悬停显示真实未复权价格；成交标记在
图上的纵向位置采用对应交易日K线高低点外侧，避免把两种价格口径画成同一纵轴价格。

### 5.2 策略选择截止日

`selection_data_cutoff`属于策略发布元数据。PTE创建账户时通过现有`strategy show`CLI
取得并作为账户不可变快照保存。字段加入`virtual_accounts`，应用层将其作为必填不可变
身份：

```text
selection_data_cutoff TEXT  # ISO日期；迁移期可空，应用层要求非空
```

SQLite升级时先增加可空列以兼容原表，再对现有账户执行一次性安全补齐：PTE通过TDR CLI
按`strategy_id/version`读取策略发布；仅当返回的`release_hash`与账户一致时写入截止日。
解析失败或哈希不一致时保留交易运行，图表显示“策略选择截止日不可用”，并记录一次系统
告警事件。迁移完成后，所有新建和身份校验路径都要求该字段非空；旧账户未补齐前只有图表
不可用。

新账户缺少截止日时拒绝创建，避免产生身份不完整的观察账户。该字段加入账户不可变身份
比较，已有相同账户的幂等创建必须验证一致。

### 5.3 PTE观察事实

PTE按账户读取：

- `decisions`：信号日、有效交易日、动作、目标持仓、决策ID；
- `intents`：方向、数量、限价、有效交易日、意图ID及状态；
- `orders`：Futu订单ID、状态和累计成交；
- `fills`：成交时间、增量数量、成交价、费用；
- `account_snapshots`：交易日实际持仓。

所有记录先按`account_id`过滤。选择截止日以前的决策、订单和成交不会进入图表，即使历史
迁移数据中存在这些记录。

## 6. 组件与契约

### 6.1 PTE图表事实构建器

新增`paper_trading_engine.account_chart`，职责为：

- 验证账户存在及截止日元数据；
- 验证PTE运行行情manifest并读取有限窗口日线；
- 从PaperStore读取账户决策、意图、订单、成交和日快照；
- 将行情与账户事实构建为版本化`account_observation.v1`请求；
- 计算内容指纹并管理缓存；
- 通过stdin调用TDR CLI，并接收stdout返回的完整HTML；
- 在PTE缓存目录中原子保存HTML；
- 将业务错误转换为只读图表状态。

它不计算信号、CZSC笔或绩效，也不修改账户账本。

### 6.2 TDR观察图渲染器

TDR新增纯转换CLI入口：

```powershell
Get-Content <account_observation.json> -Raw |
  czsc-trader chart observation --format html > <observation.html>
```

该命令：

- 只从stdin读取一份`account_observation.v1`，校验行情、日期、标的和事件字段；
- 复用`charting.py`的日K、透明悬停点、CZSC笔、缺失交易日和Plotly配置；
- 叠加截止区间、PTE信号、意图、成交和持仓轨迹；
- stdout只返回自包含HTML，stderr承载诊断；
- 不读取PTE数据库、PTE运行目录或TDR行情目录；
- 不调用Tushare，不写行情、HTML、策略或研究档案。

PTE使用`subprocess.run(input=..., capture_output=True, shell=False)`传输请求，校验退出码、
HTML内容和超时后自行原子保存stdout。冷生成超时固定为30秒，输入上限5MB，输出上限
20MB。`chart observation`是面向PTE的机器契约，TDR在整个流程中只持有进程内数据。

### 6.3 请求契约

`account_observation.v1`至少包含：

```json
{
  "contract_version": "account_observation.v1",
  "account": {
    "account_id": "s001-v2",
    "strategy_id": "S001",
    "strategy_version": "v2",
    "release_id": "S001-v2",
    "release_hash": "...",
    "selection_data_cutoff": "2026-09-02",
    "symbol": "588080.SH"
  },
  "context_sessions": 180,
  "market_data": {
    "manifest_sha256": "...",
    "adjustment": "hfq",
    "bars": [
      {"date": "2026-09-02", "open": 1.0, "high": 1.1, "low": 0.9, "close": 1.05}
    ]
  },
  "decisions": [],
  "intents": [],
  "orders": [],
  "fills": [],
  "snapshots": []
}
```

TDR拒绝未知顶层字段、非法日期、非递增或重复K线、账户与记录作用域不一致、重复身份和
截止日前观察事件。数值字段必须为有限数，OHLC关系必须有效，数量必须为整数。TDR不会
把请求体、行情或HTML写入磁盘。

### 6.4 缓存

缓存位于：

```text
state/paper_trading/charts/<account_id>/
  observation.html
  observation.meta.json
```

指纹包含：契约版本、账户不可变身份、选择截止日、180日配置、行情manifest哈希，以及
该账户决策、意图、订单、成交和快照的规范化内容。指纹相同则直接复用HTML。

PTE把TDR stdout写入同目录临时文件并原子替换。每个账户使用独立进程内锁；并发请求共享
一次生成。缓存属于PTE本地运行态，被Git忽略，重启后可复用，删除后可安全重建。TDR不
接收缓存路径，也不保存生成结果。

### 6.5 HTTP

新增：

```text
GET /api/virtual-accounts/{account_id}/chart
GET /charts/{account_id}/observation.html?v={fingerprint}
```

首个接口返回：

```json
{
  "scope": {"account_id": "s001-v2", "release_id": "S001-v2"},
  "status": "READY",
  "selection_data_cutoff": "2026-09-02",
  "context_sessions": 180,
  "chart_url": "/charts/s001-v2/observation.html?v=...",
  "fingerprint": "...",
  "message": null
}
```

`status`取`READY/EMPTY/UNAVAILABLE`。HTTP层校验账户ID并只允许服务预期缓存目录中的固定
文件，禁止任意路径读取。图表响应允许ETag缓存；账户和系统API继续`no-store`。

## 7. 更新时序

账户页加载时并行请求账户快照和图表状态。PTE图表构建器先计算指纹：

```text
指纹命中 → 返回现有chart_url
指纹未命中 → PTE传入内存数据 → TDR返回HTML → PTE原子发布 → 返回新chart_url
生成失败 → 返回UNAVAILABLE，交易主链路继续运行
```

正常轮询只重新请求轻量图表状态。指纹变化时替换iframe URL；指纹不变时不触碰iframe。
预计单次冷生成允许数秒，热读取应在本地文件和SQLite查询量级完成。

## 8. 错误与审计

图表生成属于只读辅助能力：

- 输入契约、数据验证、TDR超时和文件写入失败统一返回`UNAVAILABLE`；
- 错误消息脱敏后显示在当前账户图表卡片；
- 同一账户、相同错误指纹只记录一次`SYSTEM`事件；恢复后记录一次恢复事件；
- 图表错误不进入`scheduler_failures`，不改变账户健康、暂停或渠道状态；
- 图表生成不记录每次成功读取，避免审计噪声。

事件类型固定为`ACCOUNT_CHART_GENERATION_FAILED`和`ACCOUNT_CHART_RECOVERED`。

## 11. 验收标准

1. 每个虚拟账户只显示自身策略身份和前瞻事实；
2. 默认窗口含截止日前180个交易日和全部前瞻行情；
3. 截止线、区域、信号、意图、成交、目标与实际持仓语义清楚；
4. 截止日前不补算账户历史信号；
5. 页面轮询不造成图表或整页闪烁，缩放状态在内容不变时保留；
6. 前瞻行情由PTE读取并传入；TDR只在内存中绘图，不保存或主动读取任何行情；
7. 图表失败不影响PTE交易与对账；
8. 现有账户完成可审计元数据补齐，新账户身份完整；
9. 两个账户切换无串图，路径不能越过缓存根目录；
10. 受影响及全量功能回归通过，文档同步完成。
