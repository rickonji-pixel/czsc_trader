# 588080动态仓位实验设计

## 目标与研究类型

本轮正式实验编号为 `0829_EX02`，检验当前活动正式基线 `baseline_20260826` 的冻结综合分数，能否在持仓期间同时承担“信号强弱”和“目标仓位”两种职责。它属于架构型研究：入场、退出和原冠军挑战规则不变，仅新增持仓内的半仓状态及其交易审计。

本轮只有一个固定挑战者，不搜索、不排序、不拟合新阈值。实验结果只回答该固定机制能否严格战胜当前冠军，不自动修改活动基线。

## 冻结状态机

- 标的固定为 `588080.SH`，冠军只从 `configs/rule_baselines/registry.json` 解析。
- 12个CZSC因子、归一化、权重、入场阈值 `0.175`、离场阈值 `0.025`、确认日、最短持有期、退出确认日、次日开盘执行、手续费和初始资金全部冻结。
- 空仓时仍按原规则确认入场；入场目标仓位固定为 `1.0`。
- 未达到原最短持有期时保持 `1.0`，不得提前减仓。
- 达到最短持有期后：`score >= 0.175` 为 `1.0`；`0.025 < score < 0.175` 为 `0.5`；`score <= 0.025` 按原退出确认变为 `0.0`。
- 半仓状态下，分数恢复到 `0.175` 或以上时恢复 `1.0`；跌至 `0.025` 或以下时按原规则退出。
- 目标仓位只在状态改变时于下一交易日开盘执行；半仓与全仓之间的转换均产生真实买卖、手续费和唯一因子事件，不做每日比例再平衡。

## 评估和PASS规则

为了保持原冠军挑战协议不变，展示窗口和PASS规则沿用既有定义：

1. 选择样本截止 `2025-12-31`，展示 `2022H1` 至 `2025H2` 八个半年窗口。
2. 因为只有一个固定挑战者，八个窗口仅用于可见样本诊断，不承担候选选择或参数拟合。
3. 挑战者在可见样本结束后写入冻结文件并计算SHA-256，之后才加载2026数据。
4. 正式比较窗口保持 `2026Q1`、`2026H1`、`2026M1-M8`，最后一个窗口仍截止原协议的 `2026-08-21`。
5. 三个窗口中挑战者费后收益率必须全部严格高于冠军才为PASS，否则为FAIL。
6. 收益率是唯一判定指标；夏普、最大回撤、持仓率、交易次数和变仓次数仅作诊断。

2026截至 `2026-08-28` 已经被项目观察；本轮不把正式比较窗口称作未见独立证据，也不根据结果修改状态规则。新独立前向证据仍从 `2026-08-28` 之后开始积累。

## 因果与资金审计

动态路径允许四类普通事件：`Entry`（`0 -> 1`）、`Reduce`（`1 -> 0.5`）、`Increase`（`0.5 -> 1`）、`Exit`（正仓位 `-> 0`）。独立窗口在期初已有持仓时仍使用 `InitialEntry` 对齐。

每笔订单必须连接同一信号日的唯一事件，且信号日严格早于下一交易日的执行日。事件的前后仓位必须与目标路径完全一致。vectorbt权益与独立逐笔资金账本必须逐日一致；冠军二元路径必须与活动基线应用结果完全一致。

## 软件和归档边界

在仓位模块新增纯动态状态机和事件生成器；扩展通用因果审计与订单溯源以支持 `Reduce/Increase`；新增独立研究处理器 `dynamic_score_zone_position_sizing`。协议漂移、身份错误、资金不闭合或审计失败均归档为ERROR，不能包装成策略FAIL。

固定产物包括协议、身份审计、可见样本诊断、冻结挑战者、2026比较指标、仓位路径、因子事件、订单、执行记录、结论和实验清单。普通 `outputs` 与隔离回放不构成研究证据。
