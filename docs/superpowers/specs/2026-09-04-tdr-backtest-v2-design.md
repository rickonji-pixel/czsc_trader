# TDR Backtest v2 设计

日期：2026-09-04  
状态：待用户书面评审  
实施分支：`codex/tdr-backtest-v2`

## 1. 背景

现有 TDR 回测围绕 `baseline_*`、`configs/rule_baselines` 和命名窗口构建，已经具备因果信号回放、次日开盘参考回测、完整执行规则模拟、指标计算、图表及基础审计能力。随着 SM、SE 和 PTE 建立，现有模型出现以下结构性缺口：

- 正式策略身份 `S001-v1` 无法直接贯穿回测产物；
- 回测执行模拟使用后复权价格，PTE advice 使用不复权执行价格；
- `audit.json` 主要覆盖次日开盘参考订单，未完整覆盖执行规则模拟；
- 回测区间依赖 `configs/backtest_windows`；
- `configs` 同时承载策略资产、旧基线、执行规则和研究窗口，领域归属混乱；
- TDR 无法使用独立持续更新的数据集与 PTE 做前瞻交叉核验。

Backtest v2 采用新核心与旧引擎短期并存的迁移路线。v2 不兼容旧接口、旧字段和旧产物格式。旧引擎只用于迁移核验，v2 验收后退役。

## 2. 目标

Backtest v2 是正式策略和研究候选共用的确定性历史回放器。一次运行应回答：

1. 给定策略在给定数据和日期范围内产生了哪些因子、目标持仓和信号？
2. 从指定初始资金空仓启动，按策略内置执行规则会产生哪些订单、虚拟成交和账户结果？
3. 输入、计算过程和结果能否被 SE 独立审计和跨机复现？
4. 对正式策略，回放决策能否与 PTE 逐日交叉核验？

## 3. 非目标

本次不实现：

- 策略与研究数据集 cutoff 的绑定治理；
- 数据污染判断或研究期、测试期、前瞻期的自动分类；
- 多标的组合、融资、做空、分红现金流和部分成交；
- 任意历史账户快照注入；
- 候选搜索算法或 SE 排名算法重做；
- 旧回测 CLI、字段和报告格式兼容层；
- PTE 实际订单或成交状态的替代账本。

## 4. 核心原则

### 4.1 一个回放核心，两类策略来源

回放核心接收不可变 `StrategySnapshot`，不检查策略生命周期状态。

- 正式策略由 SM 解析，例如 `S001-v1`；
- 研究候选由实验工作流解析，例如 `0904_EX04:R1102`；
- 两类快照都必须包含完整策略规则、完整执行规则、来源信息和内容哈希；
- `PAPER_READY` 仅是 PTE 部署门槛，不是 TDR 回测门槛；
- 大量候选不进入 SM，避免污染正式策略注册表。

### 4.2 明确日期，不使用命名窗口

一次 TDR 回测只处理一个显式日期区间：

- `start`、`end` 必填；
- `end` 同时约束本次可见数据的截止日；
- 删除 `--windows` 和 `--window`；
- TDR 不理解 `2026FULL`、研究期或测试期等业务标签；
- 多年度、多周期评估由 SE 显式编排多次回放。

### 4.3 回测中立，研究治理外置

TDR 记录数据事实，不判断数据污染。数据污染通过受控研究工作流解决。策略与研究数据集 cutoff 的绑定在后续独立治理任务中设计。

### 4.4 一套执行语义

TDR advice 和 Backtest v2 共用限价计算、tick 取整、目标数量计算、交易周期状态转换和买卖方向判断等纯函数。策略只携带一套冻结执行规则，普通回测不能通过 CLI 覆盖它。

## 5. 目录与领域归属

目标仓库结构：

```text
czsc_trader/
├── strategies/          # SM正式策略、版本、资格和证据
├── experiments/         # 研究协议、候选、区间和实验产物
├── data/
│   ├── raw/             # 当前冻结研究池
│   └── backtest/        # TDR独立维护的追加式回测数据集
├── outputs/             # 回测输出
├── src/                 # 程序
└── state/               # 本机运行状态，不入Git
```

`configs` 最终删除：

| 旧目录 | 处置 |
| --- | --- |
| `configs/strategies` | 迁移到根目录 `strategies/` |
| `configs/backtest_windows` | 新代码不再读取；历史引用按审计需要随实验保留或归档 |
| `configs/rule_baselines` | 旧引擎退役后删除；必要历史证据进入 `archive/legacy/` 或对应实验 |
| `configs/execution_policies` | 执行规则已进入策略快照；必要历史证据归档 |

迁移前必须扫描全部代码、测试、文档和实验引用。仍承担历史证据职责的文件先归档，再删除 `configs`。

## 6. 数据设计

### 6.1 研究池 `data/raw`

- 当前数据固化为研究池；
- 本次任务不实现策略级 cutoff 绑定；
- 研究候选继续由受控实验流程读取该目录；
- 研究池升级属于后续治理任务。

### 6.2 回测数据集 `data/backtest`

- 由 TDR 独立维护；
- 首次从研究池完整初始化，保留足够因子预热历史；
- 后续持续追加新交易日；
- 同时包含后复权信号行情和不复权执行行情；
- 已发布交易日默认不可修改，发现差异时拒绝更新并报告；
- 数据发布与回测运行分离，回测命令不隐式联网更新；
- 每次回测按 `end` 截断可见数据并计算输入指纹。

TDR 提供独立的数据更新入口。具体命令名称在实施计划中统一，但必须满足：显式调用、原子发布、失败不破坏旧数据、生成清单和哈希。

### 6.3 价格语义

- 因子和目标持仓使用后复权 30 分钟、日线和周线行情；
- 委托限价、成交价、手续费、交易数量和账户估值使用不复权执行行情；
- 盘中限价触发使用不复权 30 分钟行情；
- 信号行情与执行行情必须覆盖相同交易日并通过日级对齐校验；
- 数据缺口、重复日期、逆序、非有限价格或哈希不一致均终止运行。

## 7. 回测请求

统一请求包含：

```text
strategy_snapshot
dataset
symbol
asset_type
start
end
initial_cash
scenario
```

约束：

- `start`、`end` 和 `initial_cash` 必填；
- 初始现金必须为正数；
- 初始账户始终空仓；
- 首版只支持一个标的；
- 普通场景完整使用策略执行规则；
- SE 压力场景可以显式提供费用或滑点变化，产物必须记录场景身份；
- 回放核心接收已解析快照，不自行判断候选或正式策略状态。

正式策略 CLI 示例：

```powershell
czsc-trader backtest run `
  --strategy S001 `
  --strategy-version v1 `
  --dataset backtest `
  --symbol 588080.SH `
  --asset etf `
  --start 2026-09-03 `
  --end 2026-09-04 `
  --init-cash 100000
```

候选策略由实验评估入口解析并在进程内调用同一回放核心，不要求注册到 SM。

## 8. 回放流程

### 8.1 信号轨道

```text
加载截止end可见的后复权行情
  → 生成完整因子预热上下文
  → 计算每日因子分数
  → 生成目标持仓
  → 识别持仓变化事件
  → 生成下一交易日有效的策略决策
```

计算上下文可以早于 `start`，评价账户和绩效严格从 `start` 开始。产物分别记录计算上下文范围和实际评价范围。

### 8.2 账户初始状态

- `start` 前账户状态固定为指定现金和零持仓；
- 使用 `start` 前一交易日已完成收盘数据计算首日目标；
- 前一日目标为持仓时，可在 `start` 形成显式初始买入；
- 不继承未知历史持仓或交易周期。

### 8.3 买入周期

目标持仓从 0 变为 1 时：

1. 使用信号日不复权收盘价计算委托限价；
2. 按策略 tick 规则取整；
3. 使用当前可用现金、费用和手数计算目标数量；
4. 目标数量在本次进场周期内固定；
5. 下一交易日开盘价不高于限价时按开盘价成交；
6. 开盘未成交时检查不复权盘中价格；
7. 最低价严格低于限价时按限价成交；
8. 仅触及限价视为无法确认成交；
9. 未成交且目标仍为 1 时，下一交易日继续尝试；
10. 模拟成交发生后才更新现金和持仓。

### 8.4 卖出周期

目标持仓变为 0 且账户存在持仓时：

1. 下一交易日优先发出全部卖出订单；
2. 使用策略冻结的可成交限价规则；
3. 回测按下一交易日开盘价模拟成交；
4. 扣除费用后更新现金；
5. 清空持仓并结束交易周期。

### 8.5 首版交易能力

- 单标的；
- 全仓或空仓；
- 整手交易；
- 单一活动进场周期；
- 全部成交或未成交；
- 无融资、做空、分红现金流和部分成交。

## 9. 产物契约

每次成功运行原子发布一个不可覆盖的目录，至少包含：

| 产物 | 内容 |
| --- | --- |
| `manifest.json` | 请求、策略身份和哈希、数据指纹、代码版本、日期范围、场景和审计状态 |
| `decisions.csv` | 每日分数、目标持仓、事件、有效交易日和决策动作 |
| `orders.csv` | 委托方向、限价、数量、信号关联、尝试次数和状态 |
| `fills.csv` | 虚拟成交时间、价格、数量、费用和触发方式 |
| `account_daily.csv` | 每日现金、持仓、成本、市值、权益和目标状态 |
| `trades.csv` | 完整买卖周期及净收益；未闭合尾仓单独标识 |
| `metrics.json` | 核心和辅助绩效指标 |
| `audit.json` | SE 审计结论及原因码 |
| `report.md` | 人类可读摘要 |
| `chart.html` | 回测图表 |

核心指标：最大回撤、卡玛比率、盈亏比及其状态。收益率、夏普率、交易数等作为辅助指标。只有完整买卖周期计入盈亏比。

输出名称只使用正式策略或候选身份，不使用“活动基线”“冠军策略”“实际执行”等漂移或易误解称谓。虚拟成交明确标记为模拟结果。

## 10. SE 审计边界

TDR 负责运行时不变量校验并生成证据；SE 独立审计证据。

最低审计项：

1. 策略快照内容哈希一致；
2. 数据清单、文件哈希和实际可见截面一致；
3. 因子、分数、目标持仓和事件日期保持因果顺序；
4. 决策只使用信号日及以前数据；
5. 委托发生在有效交易日且引用唯一决策；
6. 委托价、tick、手数和目标数量符合策略规则；
7. 虚拟成交符合开盘和盘中触发规则；
8. 未成交订单不改变账户；
9. 现金、持仓、费用和每日权益逐日守恒；
10. 完整交易配对和指标重算一致；
11. 相同输入重复运行得到相同结构化产物。

PTE 交叉核验由 TDR 产出预期决策证据，PTE 提供实际决策、订单与成交账本，SE 执行比较。渠道成交回报始终是 PTE 实际账户的事实来源。

## 11. 失败处理

- 运行先写入临时目录；
- 所有计算、产物写入和 SE 审计通过后才原子发布；
- 失败不生成看似完整的正式回测目录；
- 命令返回稳定错误码、简明消息和结构化上下文；
- 网络更新失败只影响数据更新命令，不影响已有数据上的回测；
- 历史数据变化、缺失不复权行情、策略哈希不符或审计失败均属于硬失败；
- 失败日志不得包含凭据。

## 12. 迁移路线

1. 新建 `czsc_trader.backtesting` 核心和新产物模型；
2. 迁移 SM 存储到根目录 `strategies/`；
3. 初始化并验证 `data/backtest`；
4. 让 advice 与 v2 复用决策和执行纯函数；
5. 在 SE 增加 v2 证据审计；
6. 建立新 `backtest run`；旧命令改为临时 `backtest legacy-run`；
7. 使用 S001-v1、S001-v2 和代表性候选做新旧回测解释性比对；
8. 使用 S001-v1 对 2026 YTD 及 PTE 前瞻日期做交叉核验；
9. 更新 README、研究交接和开发交接文档；
10. 验收后删除旧引擎、旧入口及无审计价值的 `configs` 内容。

新旧结果无需数值完全一致。所有差异必须能够归因于已确认的语义修复，例如正式策略身份、不复权执行价、整手数量或更完整的成交规则。

## 13. 测试与验收

遵循 OPC 测试治理，保留少量覆盖完整能力的功能测试：

1. 正式策略端到端回测；
2. 研究候选通过同一核心回测；
3. 不复权限价、整手数量和未成交重试；
4. 数据缺口、哈希变化和历史行修改失败；
5. SE 对篡改决策、订单、成交和账户数据的拒绝；
6. 相同输入重复运行的确定性；
7. advice 与 backtest 的同日决策和委托意图一致；
8. S001-v1 在 PTE 已有日期上的信号交叉核验。

完成标准：

- `configs` 不再被生产代码读取；
- TDR 回测可以直接使用正式策略身份和候选快照；
- 信号价格与执行价格语义分离且全链路一致；
- 所有成功产物通过 SE 审计；
- PTE 能使用回测证据解释每日策略决策；
- 旧引擎退役后，功能测试和端到端交付验证通过。
