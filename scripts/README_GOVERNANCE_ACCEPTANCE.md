# 三节点治理流程验收

## 用途与边界

用隔离的完整演练验收“立项 → 候选送审与独立复核 → 人工批准冻结”，无需启动真实研究批次。
执行脚本为 `scripts/acceptance_governance.py`，全部产物写入 `.tmp/governance-acceptance-时间戳/`。

- 调用正式 CLI，使用真实的 TDR、SE、TXE 和 SM 实现，不替换计算函数或回填通过报告。
- 生成确定性的合成行情及辅助输入，经过正式文件加载器、SRT、DFLS 发布和 TXE 执行。
- 使用 12 个预先定义的候选配置，固定送审 `S900-C001`；准备阶段真实重算收益声明，
  送审阶段在独立封存的数据集上再次计算，禁止复用评估产物。
- 将 `tests/fixtures/candidate_runtime.py` 复制进临时 SRT 包；送审前实现候选 SRT，
  冻结时同一实现获得版本身份，并检查实现、参数、数据和执行契约保持一致。
- 合成行情、候选池和验收目标都是软件验收夹具，不代表真实研究证据，
  不能用于确认 Alpha、修改历史审计结论或批准真实策略部署。
- 外部复现按演示契约明确不要求；监测方案的批准由演示参与人给出，机器只检查其结构与状态。
- SRT 验收覆盖加载、实现哈希和输入/执行契约一致性；不连接数据供应商、不部署 PTE、不下单。
- 正式 `strategies/`、历史实验和 PTE 状态不作写入。脚本另核对正式策略 JSON 的前后哈希。

## 执行

在项目根目录使用已安装项目依赖的虚拟环境运行：

```powershell
.\.venv\Scripts\python.exe -B scripts/acceptance_governance.py
```

需要安装项目及子包依赖，并保留仓库中的候选 SRT 测试夹具。
本演练不需要行情接口密钥或历史实验产物；真实行情回放另用 `scripts/acceptance_srt_txe.py` 验收。
每次运行创建独立目录，已有验收产物不会被覆盖。

## 验收场景

| 场景 | 操作 | 应观察的结果 |
| --- | --- | --- |
| 正常三节点 | 立项、送审、真实评估、批准冻结 | 同一治理凭据逐级追加，生成一个冻结版本 |
| 重复冻结 | 对同一凭据再次冻结 | 返回幂等结果，版本及治理记录不重复写入 |
| 收益错报 | 提交的年化收益比真实值高 100 个百分点 | `CLAIM_MISMATCH`，冻结失败，无版本产物 |
| 必需证据缺失 | 移除演示监测方案 | `AUDIT_MISSING:monitoring_plan`，冻结失败，无版本产物 |
| 评估后证据变化 | 改动已评估的指标文件 | 冻结时报告证据变化，无版本产物 |

## 如何人工复核

打开本次输出目录：

1. `acceptance.json`：总结果、各案例断言、正式策略文件是否保持不变。
2. `normal/adjudication.json`：真实指标复核、九类审计的状态和保留意见。
3. `normal/strategies/S900/credentials/SGC-S900-001.jsonl`：检查同一凭据的逐层盖章。
4. `normal/strategies/S900/versions/v1.json`：检查版本对凭据及评估的引用。
5. 各场景 `logs/`：完整命令参数、退出码、耗时、标准输出和错误输出。
6. `false_claim/`、`missing_evidence/`、`evidence_drift/`：检查拒绝原因及版本未落盘。

若运行中断，查看 `failure.json` 和已保留的日志。没有 `acceptance.json` 的 PASS 结果即未完成验收。
该演练用于版本验收，不加入每次开发的默认快速回归。
